### Как описывать запрос и ответ

- `request.path` — путь на этом же сайте. Значения, которые зависят от студента (идентификатор аккаунта и т. п.), берутся шагом `bootstrap`: GET с ответом JSON, `extract` сопоставляет имя параметра с указателем JSON; потом путь или запрос используют `{имя}`. Имена параметров — латиница и цифры.
- Даты и время в `query` — шаблонами: `{today}`, `{weekStart}` (понедельник текущей недели в часовом поясе источника), `{plusDays:N}`, `{minusDays:N}`, `{nowUnix}`. Если адрес человека выбирает текущую неделю с понедельника, используй `{weekStart}`, сохранивая выбранную неделю при проверке, включая уже прошедшие занятия. Не заменяй такой адрес на «сегодня» и не копируй календарную дату как константу. Для произвольной исторической недели уточни намерение, не выдавай текущую за выбранную.
- Ответ JSON: `format: "json"`, `itemsPath` — указатель на массив записей (`""` — сам корень), у поля `path` — указатель внутри записи, `transform` — один из `iso`, `unixSeconds`, `unixMillis`, `trim`, `number`, `bool`, `html2text`, `joinNames`. Для даты со строкой — `iso`; для числа секунд — `unixSeconds`.
- Ответ HTML: `format: "html"`, `itemsSelector` — селектор одного элемента списка, у поля `selector` — селектор внутри элемента (`"."` — сам элемент), `attr` — если значение лежит в атрибуте (`href`, `datetime`, `data-…`), `transform` — как выше. Выбирай устойчивые селекторы: классы смысла, а не позиции.
- Предпочитай подтверждённый HTTP JSON/HTML. Если записи есть только в отрисованном DOM SPA, для GET+HTML можно явно задать `request.render: true`: тот же селектор будет проверен настоящим фоновым браузером. Это дороже HTTP (не больше трёх страниц и 30 секунд на чтение) и не подходит для POST, обхода защиты или действий на странице. Не считай наличие DOM доказательством работающего HTTP — оба режима проверяет canary.
- Пагинацию (`pagination`) описывай, только если в наблюдениях видно, что ответ постраничный.
- Расписание, которое источник отдаёт окном от даты в query (`begin_date`, `from`, `date`), читай по нескольким окнам: `pagination: {"type": "dateWindow", "param": "<ключ query с шаблоном даты>", "stepDays": <сколько дней покрывает одно окно, обычно 7>, "windows": 6, "startOffset": -1}`. Это прошлая неделя, текущая и четыре следующие. `stepDays` возьми из наблюдений: если ответ на соседнюю дату начинается ровно через `stepDays` дней после предыдущего, окна не перекрываются. Один ответ — это только окно вокруг сегодняшнего дня: недели с контрольной или каникулами бывают почти пустыми, а следующие — полными. В идентификатор записи (`identity`) обязательно входят дата и время начала, иначе одинаковые занятия разных недель сольются.
- Если подходят несколько источников, верни до трёх вариантов, лучший первым. Поле `doubts` — до трёх коротких сомнений, если они есть.

- Для `scheduleEvents` кроме обязательных полей заполняй то, что есть в записи: `kindText` — тип занятия словами источника, `address` — адрес здания, `group` — группа или поток, `lessonNumber` — номер пары (`transform: number`). Онлайн-ссылки описывай секцией ответа `links` (до 4): `{"url": <указатель>, "label": <указатель на подпись или общий текст>}`. Остальные полезные значения (корпус, подгруппа, форма контроля) — секцией `attributes` (до 8): `{"label": "<общая подпись>", "path": "<указатель>"}`. Подпись — общий текст («Корпус»), а не значение из ответа. Поля `links` и `attributes` в `fields` не пиши. Эти секции доступны только в формате v2.
