# Инструкции для агентов, работающих в этом репозитории

Проект: **BotAI** — учебный хаб студента (PWA) для владельца и его друга.
Агент внутри приложения подключает вузы, читает и склеивает источники, отвечает
на вопросы и выполняет учебные действия. **Пивот v4 (свободный harness) реализован
в коде**; в production двигатель включается флагом `BOTAI_AGENT_ENGINE=v4` после
приёмки. Источник правды — [docs/v4/](docs/v4/README.md); старые ADR удалены.
Текущий статус и остатки — [README v4](docs/v4/README.md#статус-реализации-2026-10-31-третья-итерация),
[handoff](docs/v4/07-handoff-claude.md).

## Принципы проекта (не обсуждаются в коде)

1. **Свобода агента — главная ценность.** У агента есть произвольная сеть,
   браузер с полным управлением, исполнение кода в песочнице, файлы, сессии,
   действия на сайтах, RAG и память. Не добавляй архитектурных запретов; если
   ограничение нужно — это решение владельца, записанное в
   [06-decisions.md](docs/v4/06-decisions.md).
2. **Pet-проект на двух человек.** Мультитенантность, публичная регистрация,
   биллинг, юридическое соответствие, SLA для чужих пользователей — не цели.
3. **Один контур.** Любая задача (подключение, синхронизация, починка, чат,
   действие) может использовать модель. Детерминированные быстрые пути — это
   оптимизация цены/скорости, а не архитектурная граница.
4. **Источник — живая запись агента.** У вуза сколько угодно источников любого
   вида; у источника сколько угодно видов данных. Знание о вузе (адреса,
   эндпоинты, селекторы, JS, код) хранится в данных и playbook'ах, а не в коде
   приложения.
5. **Секреты: первичные скрыты, сессия доступна.** Пароль, код MFA и ключ-ссылка
   не попадают в промпт, историю и логи: только Vault/secret broker/защищённые
   поля. Cookie, токены, storage, HAR — рабочий материал агента, он может их
   читать и переиспользовать.
6. **Действия разрешены по политике.** POST, формы, заявки, изменения на сайтах
   выполняются по настройке владельца (`auto`/`ask`/`never`), с журналом и
   идемпотентностью. Деструктивное и денежное по умолчанию спрашивает.
7. **Живые вузы — норма проверки.** Живой прогон с реальными кредами важнее
   фикстур. Креды — только через secret broker (Keychain/файл 0600), никогда в
   репозитории, чате, логе, артефакте.
8. **Полная трассировка.** Шаги агента, запросы, ответы, DOM, скриншоты, клики и
   изменения данных сохраняются; агент может читать свои и прошлые трассы.
9. **Не трогай чужой каталог.** Изменение контракта — отдельный PR в `contracts/`
   с перечислением, кого оно ломает.
10. **Честность.** Не выдумывай проценты прогресса, сроки и источники.
    Непроверенное помечай явно.

## Команды

```bash
make db          # Postgres для разработки (127.0.0.1:55432, pgvector/pgvector:pg17)
make check       # полный локальный гейт: ruff, pyright, pytest, Biome, tsc, vitest, gen
make gen         # пересобрать контракты/OpenAPI/TS-типы
make migrate     # alembic upgrade head на dev-БД
make bench SCENARIO=B1 ARGS="..."            # агентский бенчмарк L2 (v3-путь)
python -m bench.live.run --scenario login    # живой бенчмарк L3, примитивы harness (из корня)
backend/.venv/bin/python -m bench.v4.run_agent --scenario l2-fakeuni  # v4-агент, $0
backend/.venv/bin/python -m bench.v4.run_agent --scenario live-hse    # v4-агент, живой ВШЭ
docker build -f ops/docker/sandbox.Dockerfile -t botai-sandbox:test .  # песочница code_exec
make dev-api / dev-worker / dev-web
```

## Качество

- `make check` должен быть зелёным: backend — ruff/ruff format/pyright strict/pytest
  с Postgres; frontend — Biome/tsc/Vitest; сгенерированные файлы без расхождений.
- Каждое поведение из требования или плана закрывается тестом. Новое поведение —
  L0/L1; живое — L3 через бенчмарк.
- PR называет пункт плана/решение и честно пишет, что осталось непроверенным.
- Русский в документации, описаниях PR и интерфейсе; английский в коде,
  идентификаторах и заголовках коммитов.
- Новые токены дизайна — только из `packages/design`, не по месту.

## Секреты и публичность

- Репозиторий **публичный**: никаких реальных кредов, cookie, токенов,
  персональных данных и секретных ссылок в коде, тестах, доках, коммитах.
- `.env` в `.gitignore`; ключи моделей — там или в Keychain, но не в git.
- Живые креды ВШЭ/ЦУ после пивота — в macOS Keychain, сервисы `botai.live.*`;
  выдаются кодом через `bench/live/secret_broker.py`. Значения никогда не
  печатаются и не попадают в артефакты; пароль-поля вычищаются из HAR/логов.
- Сырые артефакты живых прогонов (сессии, скриншоты, HAR) — только вне
  репозитория: `~/.local/state/botai-v4-bench/…`, права 0700.

## Чего не делать

- Не восстанавливать удалённые ADR и отменённые ограничения (два контура,
  запрет кода, egress allowlist, read-only, запрет капчи, вырезание сессии,
  «ничего под конкретный вуз», жёсткие бюджеты, запрет живых тестов).
- Не спрашивать разрешение на то, что уже разрешено в `06-decisions.md`.
- Не добавлять инфраструктурный узел «на всякий случай»: Redis/Kafka/отдельный
  векторный сервис — только под конкретное ограничение.
- Не ломать production без бэкапа; деплой по SHA, миграции проверять на копии.
