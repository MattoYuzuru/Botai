## Что осталось (по приоритету)

**Статус на 2026-11-01 (третий срез):** production работает на `BOTAI_AGENT_ENGINE=v4`.
Фазы 3.3 (фоновая автономия: `sources.next_sync_at` + scheduler + бэкофф) и 3.4 (расход/лимиты
в UI) реализованы; RAG-автоиндексация после успешного sync включена; async `sync-jobs` (202) и
`DELETE /sources/{id}` добавлены; в UI — расход, удаление источника, «Следующее обновление»,
название источника в журнале. Живой L3 v4: **3/3 success** (2 новых прогона на `a0c0ade`),
медиана 135.3 с / $0.013, security gate чистый; всего за все живые прогоны $0.108065. Осталось —
ниже.

1. **Живая проверка владельцем на v4.** Открыть приложение, подключить/переподключить вуз,
   пройти вход, проверить «Учёбу», расписание/задания, чат (v4), трассы запусков и политики
   действий; откат флага — одна строка в `compose.vars` + перезапуск api/worker.
2. **Async sync и docker-сокет API.** Additive `POST /sources/{id}/sync-jobs` (202) и
   `DELETE /sources/{id}` готовы; inline `POST /sources/{id}/sync` пока остаётся основным для UI,
   поэтому API всё ещё держит docker-сокет для браузерного sync — перевести UI на 202 и убрать
   сокет из API (следующий шаг).
3. **RAG:** живой API-провайдер эмбеддингов (нужен ключ; `BOTAI_RAG_DIMENSION` фиксируется до
   миграции); автоиндексация подключена к успешному sync, но CONNECT-без-playbook и REPAIR-путь
   хукаются только следующим sync/`reindex_rag`; bounded-чистка RAG-корпуса при удалении
   источника (документы/чанки сейчас остаются, embeddings.source_id → SET NULL).
4. **Действия и RAG в живом L3.** Повторы L3 (n=3) закрыты; остаётся живой прогон action/write и
   RAG-ответа с независимой оценкой, сравнение с Codex/Claude Code (план §4.3), ЦУ/другие вузы.
   Расписания health/repair сверх sync (3.3) — не входили.
6. **Чистка легаси после приёмки v4:** удалить v3-мосты (`learn/`, старые job-пути, v3-only
   моки/документы), если они перестали быть нужны; production-данные — после бэкапа (D-016).
7. **Документация:** обновлять по факту каждого выпуска; живые прогоны — с SHA, стоимостью и
   честным списком проверенного/непроверенного.

## Границы свободы (не менялись)

- **Можно:** произвольная сеть, браузер с полным управлением, клики/ввод/JS, cookie/storage/HAR,
  запуск кода в песочнице, POST/PUT/формы, обход капчи и антибота техническими средствами,
  действия по политике владельца, свои трассы, Claude/DeepSeek/любые модели.
- **Нельзя только того, что вредит владельцу:** сливать пароли/MFA/ключ-ссылки в промпт, логи,
  историю, репозиторий; ломать чужие аккаунты/сервисы; удалять данные без бэкапа; выходить за
  pet-масштаб в мультитенантность.
- **Секреты:** первичные скрыты от модели и проходят через Vault/broker; сессия (cookie,
  токены, storage) — рабочий материал агента (D-008). Репозиторий публичный: никаких реальных
  кредов, cookie, персональных данных в коде/доках/тестах/коммитах; сырые артефакты живых
  прогонов — вне репозитория.

## Чего не делать

- Не спрашивать разрешение на действия, уже разрешённые в [06-decisions.md](06-decisions.md).
- Не восстанавливать старые запреты (два контура, allowlist, read-only, запрет кода/капчи,
  вырезание сессии) даже «для безопасности».
- Не выдавать непроверенное за проверенное: живой прогон фиксируется SHA, датой, сценарием,
  барьером и стоимостью; без этого — «не проверено».
- Не ломать production: деплой по SHA, бэкап перед миграциями, миграции на копии; v3 остаётся
  рабочим до приёмки v4.
- Не строить инфраструктуру «на всякий случай» (Redis/Kafka/отдельный векторный сервис) —
  только под конкретное ограничение.
