# Защищённые календари и компактное расписание

Исправления от 2026-11-02 по D-004, D-008 и D-031. Этот документ описывает
изменение кода; сам по себе он не подтверждает выпуск в production.

## Импорт ссылки

Раньше `secret_request` выдавал агенту handle, но `source_create(link=...)`
ожидал адрес. Агент не мог сохранить защищённую ссылку календаря для импорта.
Теперь `link` принимает handle: исполнитель получает адрес через broker,
сохраняет его в Vault как `ical_url` и возвращает безопасный `readUrl={secret}`.
Агент использует этот маркер в `source_read_live` и в reads обработчика.
Runner подставляет адрес только при запросе; ссылка не становится Bearer-заголовком.

Сохранённая ссылка принадлежит источнику: повторные sync/repair не зависят от
временного handle исходного чата. Адрес и его ключи маскируются в доступном
агенту ответе, ошибках и артефактах. В идентичность календаря входит хеш полной
ссылки, включая секретные параметры: два разных экспорта одного хоста не
схлопываются в один источник.

Идентичности старых источников автоматически не переписываются. Их ID и
обработчики сохраняются; повторное создание старого календаря с секретом в
query может создать второй источник, поскольку прежний алгоритм выкидывал этот
параметр перед хешированием. Уже выключенные пустые источники не импортируются
автоматически: агенту нужен новый запуск подключения.

Защищённый ответ обозначается «Данные переданы» и на клиенте, и в сохранённой
истории: это корректно для ссылки, пароля и кода подтверждения. Старые сообщения
истории не переписываются.

## Расписание

На компьютере карточка показывает время и краткое название. Наведение или
фокус с клавиатуры плавно раскрывает подробности вниз в потоке страницы.
На сенсорных устройствах подробности остаются открытыми; системная настройка
уменьшения анимации учитывается.

Пересекающиеся интервалы выбранного дня собираются в одну визуальную группу.
Нажатие открывает подробности всех участников с отдельными названиями,
временем и источниками. События сохраняют свои ID; визуальная группа не является
склейкой данных или автоматическим выводом о занятости. Соседние интервалы,
у которых конец одного равен началу другого, не пересекаются.

Событие на весь день отображается как «Весь день». Обработчику рекомендуется
передавать `attributes: [{"label": "Весь день", "value": "Да"}]` для iCal
`VALUE=DATE`, учитывая исключительную границу `DTEND`. Для старых записей без
атрибута используется совпадение границ с полуночью в часовом поясе вуза;
24-часовое событие с такими же границами без явного атрибута неотличимо от
события на весь день. Доступность и точечные брони внутри неё остаются отдельными
событиями независимо от приоритета источников.
