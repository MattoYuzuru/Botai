# BotAI v4: свободный harness

Статус: **пивот реализован в коде, 2026-10-31; включение v4 в production — по итогам
приёмки.** Этот каталог заменяет все ADR (0001–0013), ограничительную архитектуру и планы,
написанные под прежнюю гипотезу. Старые документы не помечаются «устаревшими» и не остаются
рядом: они удаляются, а всё, что в них было верного, переносится сюда. Репозиторий — источник
правды для следующей команды, и в нём не должно остаться ограничений, которые владелец отменил.

Текущее состояние одной строкой: свободный harness v4 (runtime, инструменты, браузер,
контейнерная песочница кода, источники/playbook'и, RAG с pgvector, UI «Учёба» без флага,
политика действий), двигатель `BOTAI_AGENT_ENGINE=v4` включается флагом; в production пока
`v3`, включение — после деплоя и приёмки (см. «Статус реализации»).

## Зачем пивот

BotAI задуман как pet-проект для владельца и одного друга: учебный хаб, который
подключает вуз агентами. Им пользуются только два человека, деньги с него не
зарабатываются, формализация не нужна. **Главная ценность инструмента — свобода
агента**, а не безопасность многопользовательского сервиса.

Сейчас архитектура выросла из двух гипотез, которых больше нет:

1. **«Один общий рецепт на всех студентов вуза».** Отсюда декларативный рецепт,
   запрет кода, allowlist хостов, вырезание личных значений, общий на весь вуз
   источник и мост между контурами обучения и исполнения.
2. **«Осторожность важнее возможностей».** Отсюда read-only по умолчанию,
   одноразовые подтверждения каждого write, отказ от обхода капчи и защиты от
   ботов, бюджеты шагов, запрет live-тестов на настоящих вузах и запрет
   показывать агенту секреты сессии.

Цель v4: агент в BotAI должен быть **не слабее любого внешнего harness** (Codex,
Claude Code, ChatGPT-агент) и удобнее их, потому что живёт внутри приложения с
источниками пользователя, RAG, памятью и интерфейсом. Если Codex может открыть
браузер, зайти в сессию пользователя, достать cookie, прочитать SPA, нажать
кнопку, отправить форму, написать и запустить код парсера — BotAI-агент тоже
должен мочь, без «архитектурных» возражений.

## Принципы v4

1. **Один контур.** Нет отдельного «обучения с моделью» и «исполнения без модели».
   Любая работа — задача агента: подключение, починка, синхронизация, ответ,
   действие. Кэш и детерминированные быстрые пути — оптимизация, а не граница.
2. **Агент — полноценный harness.** У него есть: произвольный HTTP, браузер под
   управлением (навигация, клики, ввод, JS, cookie/storage, перехват запросов),
   исполнение кода (Python/JS) в песочнице, файловая система, сессии и долгая
   работа, RAG, память, права на действия. Никаких «модель не придумывает URL и
   селекторы» — придумывает, проверяет и исправляет сама.
3. **Всё есть источник.** У вуза сколько угодно источников любого вида: сайт,
   раздел сайта, LMS, API, календарь iCal, Google/Outlook, файлы, документы,
   почта. Источник — не «вид адаптера», а живая запись «что это, где лежит, как
   читать, чем обновлять». Один вуз — одна сущность в интерфейсе.
4. **Секреты скрываются от модели, а не от инструментов.** Пароли, коды MFA,
   ссылки-ключи не попадают в промпт и историю, но агент может пользоваться ими
   через broker и браузерный контекст. Сессия (cookie, токены, storage) — рабочий
   материал агента: он может её прочитать, экспортировать и переиспользовать.
5. **Права настраивает владелец, а не архитектор.** Действия на сайтах (POST,
   PUT, отправка форм, заявки) разрешены. Политика «что можно автоматически, что
   спросить, что запрещено» — настройка пользователя, а не запрет в коде.
6. **Наблюдаемость по умолчанию.** Каждый шаг агента, запрос, кадр, клик,
   ответ модели и изменение данных трассируются и доступны агенту и владельцу.
   Ограничения на логи снимаются: логи — топливо для починки.
7. **Оцениваемость.** У пивота есть живой бенчмарк на настоящих учётных данных
   владельца: логин, чтение, динамическая страница, API, действия. Креды
   скрипта не видны агенту; результат виден и измерим.
8. **Pet-проект.** Мультитенантность, биллинг, публичная регистрация, юридическое
   соответствие, SLA для чужих пользователей — не цели. Целимся в удобство и
   возможности для владельца и друга.

## Что удаляется и почему

Полный список с цитатами, кодовыми точками и ценой каждого ограничения —
[01-as-is.md](01-as-is.md). Коротко, что отменено:

| Отменяется | Почему |
|---|---|
| Два контура и «рецепт как единственный мост» | Нет общей аудитории; мост нужен был для исполнения без модели. Модель есть всегда |
| Запрет агенту писать код парсеров | Парсер — обычный инструмент; пишется агентом, хранится версией, запускается в песочнице |
| Фиксированный набор адаптеров и DSL | Источник описывает агент; DSL остаётся удобным форматом, но не потолком |
| EgressProxy с allowlist и обязательное согласие на хост | Сеть нужна агенту произвольно; прокси остаётся для логов/маршрутизации, не для запрета |
| Read-only по умолчанию, одноразовые подтверждения write, список запрещённых действий | Права — настройка владельца, аудит вместо запрета |
| Запрет обхода капчи, stealth-плагинов, подделки отпечатка | Используется собственное устройство и собственная сессия владельца; защита от ботов — техническая задача, а не табу |
| Бюджеты шагов, представлений, запросов, токенов на раунд | Заменяются мягкими пользовательскими лимитами стоимости и наблюдаемостью, а не глухими стенами |
| «Ничего под конкретный вуз» как закон | Знание о вузе живёт в данных/playbook'ах; агент может сохранять любые найденные адреса, селекторы, JS |
| Запрет live-тестов на настоящих вузах | Живой прогон — главный источник правды; выполняется бенчмарком с секретным вводом |
| Очистка наблюдений от cookie/bearer перед отправкой модели | Сессия — рабочий материал; в промпт не попадают только первичные секреты (пароль, MFA, ключ-ссылка), и это выбор инструмента, а не стена |
| Запрет «Мои материалы», split «документы и вложения», один календарь на вуз | У вуза сколько угодно источников; UI показывает вуз и его источники, данные склеиваются |
| Квоты модели как архитектурный предохранитель | Остаётся наблюдаемость и аварийный стоп владельца |

## Что сохраняется

- Python (FastAPI + worker), PostgreSQL, React/Vite PWA, Playwright, Vault для
  шифрования секретов, Postgres-очередь, дизайн-токены, маскот Варя.
- Идея «агент сам подключает вуз и хранит выученное в БД».
- Артефакты: рецепты/playbook'и, снапшоты страниц, RAG-чанки, трассы заданий.
