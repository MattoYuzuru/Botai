## Что доказано / что нет

Смотрите `proven`/`notProven` в каждом JSON и раздел ниже. Базовое правило: успех = `status=answer` **и** артефакт в workspace **и** проверка секретов чистая; живой прогон одного SHA не доказывает качество агента в целом (D-010).

Барьер `step_limit` — это исход бюджета шагов, а не отказ инструментов: цепочка не завершена за отведённые шаги, данные могли быть уже получены. Для приёмки он значит «не доказано», даже если часть шагов прошла успешно. Запуски с `workaround` (обход известного бага) помечены отдельно и **не являются** product-path приёмкой.

`partial` — данные получены и сохранены в workspace, но финальный ответ не дан (обычно шаговый бюджет). Для приёмки это **не** успех: успех требует `status=answer`.
