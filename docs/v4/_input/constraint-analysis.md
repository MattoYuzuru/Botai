# Входной документ: анализ ограничений (прислан владельцем)

Источник: анализ, присланный владельцем 2026-10-31 (сгенерирован внешним агентом
по текущей документации BotAI). Используется как чек-лист для аудита: каждое
утверждение нужно подтвердить или опровергнуть по текущим документам и коду,
с указанием файла и строки. Ссылки на ADR и разделы — на момент до пивота; после
пивота эти документы удаляются, поэтому в [01-as-is.md](../01-as-is.md) важны
цитаты, а не ссылки.

---

Главное решение, из которого вытекает большинство ограничений: **два контура**.
В контуре обучения агент с LLM один раз изучает вуз, человек при этом рядом. В
контуре исполнения обычный sync работает по декларативному **рецепту** без модели.
Рецепт — единственный мост между контурами (ADR-0002). Ниже ограничения по
группам: что запрещено, зачем и что мы теряем.

## 1. Агент не пишет код, только декларативные спецификации

| Ограничение | Зачем | Цена |
|---|---|---|
| Агент не пишет код парсеров, JS и регулярные выражения. Он пишет рецепт или спецификацию адаптера, их проверяют JSON Schema и lint (ADR-0005) | Текст со страницы вуза не может превратиться в код на сервере | Если источник нельзя описать DSL, подключение честно завершается как неполное («unsupported capability»). Модель на лету его не «додумывает» |
| Адаптеров всего несколько: `recipe`, `moodle_ws`, `ical`, `document`. Новый вид добавляется через PR и ADR | Всё разнообразие хранится в данных, а код маленький и покрыт тестами | Нестандартный источник ждёт, пока DSL расширят. Полный RFC 5545, свои календари и произвольные действия на сайте не поддерживаются (ADR-0012) |
| В sync нет LLM | Детерминизм и почти нулевая цена каждой синхронизации | Задачи, где нужно рассуждать над содержимым страницы, идут отдельным путём (RAG, живое чтение) и считаются менее надёжными |
| В исследовании модель выбирает действие из наблюдённых элементов по ID. Свои URL, селекторы, клики и HTTP-запросы она не придумывает (ADR-0010) | Модель не может «нажать что-то опасное» | Обычный клик запрещён. Разрешены только проверенные элементы: ARIA-вкладки, `rel=next`, нативные контролы |
| Бюджеты исследования: 10 шагов, 12 представлений, 200 запросов, 90 с, 150k токенов на раунд, плюс общий бюджет задания | Защита от зацикливания и от расхода общего ключа | Исчерпанный бюджет означает «исследование неполное», а не «данных нет». Иногда это требует повторного прохода |
| Один рецепт на один origin. Lint отклоняет личные значения (e-mail, JWT, UUID, числа от 6 цифр), абсолютные URL и чужие хосты | Рецепт общий для всех студентов вуза. Отравленный рецепт стал бы каналом утечки между пользователями (угроза T6) | Источник, данные которого лежат на нескольких хостах, становится несколькими подключениями |

## 2. Только чтение по умолчанию

- **Write-действие выполняется только по одноразовому подтверждению конкретного
  запроса.** Подтверждение привязано к методу, URL и `sha256(body)`, живёт около
  5 минут и используется один раз. Режима «одобрять такие всегда» нет. Цена:
  автоматизации действий в вузе нет совсем, каждое подтверждает человек.
- **Список запрещённых действий, которые не выполняются даже с одобрением.**
  Удаление и отзыв работ, финальная сдача, смена пароля, почты или телефона,
  logout, отписка от курса, любые `DELETE`, оплаты.
- **Рецепты делают только GET.** POST разрешён только из белого списка в коде
  (два метода Moodle).
- **У агента нет инструмента «отправить данные на URL».** Адрес запроса всегда
  определяется origin подключения, а не текстом. Это защита от prompt injection.
- **`browse_source` у агента принимает два параметра: `connection_id` и `url`.**
  Только GET, адреса со словами-действиями (`/logout`, `delete`, `sesskey=`)
  отклоняются, до 3 рендеров за ход.
- **Решения агента о вашей настройке (основной источник, отключение) срабатывают
  только по нажатию кнопки, которое поставило приложение** (FR-054). Слова «да»
  или «основной» в сообщении ничего не меняют.

## 3. Сеть наружу

- **Весь трафик идёт через EgressProxy с allowlist на каждое подключение.** Только
  HTTPS:443, без IP-литералов, приватные диапазоны блокируются, DNS пинится
  против rebinding. Перехват `route` в Playwright защитой не считается: он не
  видит серверных редиректов (§4.1).
- **Новый хост добавляется только с согласия человека.** Sync, поиск и модель
  сами список не расширяют. Цена: вход через внешний SSO требует лишнего вопроса
  «разрешить?».
- **Файлы страницы (CSS, JS, шрифты) с чужих CDN загружаются при условиях:** GET,
  без cookie и `Authorization`, не больше 16 хостов на вход. Чтение агентом
  вообще не получает хостов для файлов. Страница со старой политикой реферера
  (`unsafe-url`) лишается стилей с CDN, но `code` и `ticket` не уходят наружу.
- **Service workers, SharedWorker, загрузки файлов и разрешения устройств
  выключены** во всех браузерных контекстах. Цена: кэш HTTP при входе тоже
  отключён, и вход каждый раз заново качает файлы.
- **Тесты не ходят в настоящие вузы.** Используется только фикстурный `fakeuni`
  на loopback, живую проверку делает владелец.

## 4. Секреты и модель

- **LLM никогда не видит пароль, код MFA, cookie, bearer и ссылку iCal.** Секретный
  ввод идёт API → Vault → воркер, мимо истории и модели. У `connect_calendar` нет
  аргумента-адреса.
- **Личную ссылку календаря нельзя просто вставить в чат.** Клиент не ставит её
  в очередь, сервер отвечает `409 secret_link_calendar` и не сохраняет сообщение.
  Это неудобно, зато ключ не попадает в историю и журналы.
- **Перед отправкой модели из наблюдений вырезаются значения сессии.** Если не
  удалось собрать полный список секретов браузера, наблюдение прекращается
  целиком: страница без очистки модели не передаётся.
- **Bearer привязан к точному origin, включая порт.** Берётся только тот токен,
  который браузер сам отправлял. Произвольные JWT из storage не собираются.
- **Чувствительные эндпоинты (профиль студента) не описываются в рецептах
  вообще** (§7 L6).
- **Квоты LLM на пользователя** действуют, хотя бюджет «не ограничивает» (Q15).
  Это защита от зацикливания агента. При исчерпании глобального предохранителя
  чат выключается, а синхронизации продолжают работать.

## 5. Капча и вход

- **Капча, проверка браузера и MFA не обходятся.** Stealth-плагины и подделка
  отпечатка запрещены. Это сигнал «нужен человек» (`user_action_required`). Цена:
  часть входов всегда ручная.
- **Страница входа работает в режиме только чтения.** POST разрешён только в окне
  шага: около 15 с после того, как человек (или Vault) отправил значение, на хосты
  входа, до 16 POST, пока набирается значение, и 4 после отправки (ADR-0001 §5).
  Телеметрия страницы до шага не уходит.
- **После 3 неудачных входов подряд — пауза на 10 минут.** Это защита аккаунта
  студента от бана.
- **Удалённый экран включается, только если выдерживает SLA.** Задержка p95 не
  больше 150 мс, первый кадр не позже 2 с. Иначе он не включается.

## 6. Архитектурные «нет»

- **Ничего под конкретный вуз.** В коде нет origin, эндпоинтов и селекторов.
  Разрешён только справочник названий без адресов. Цена: даже ВШЭ и ЦУ
  подключаются через обучение агента, а не готовым пресетом.
- **Нет Redis, Kafka и отдельного векторного движка без ADR.** Очередь работает
  на Postgres `SKIP LOCKED`, поиск — Postgres FTS `russian`, эмбеддинги стоят за
  интерфейсом (`NoopEmbedder`) (ADR-0003, 0006).
- **Отложено осознанно:** горизонтальное масштабирование (один сервер, один пул
  воркеров), мультирегион, публичная регистрация и биллинг, нативные приложения
  (только PWA), Telegram.
- **Агент отказывает в задачах не про учёбу** (FR-052).
- **Нельзя выдумывать проценты прогресса и выдавать ответ без источника за
  подтверждённый.** Цена: интерфейс иногда честно пишет «неизвестно».

## Обратная сторона: где ради функционала приняли риск

- **Пароль хранится, и сервер может его расшифровать (Q8–Q9).** Без этого
  невозможен автоматический повторный вход. Утечка БД без KEK паролей не
  раскрывает, утечка БД вместе с KEK — раскрывает. При выходе за круг знакомых
  это **блокирующее** условие.
- **Оператор сервера технически видит ввод при входе (T8).** Принято, потому что
  оператор — это владелец.
- **Канал GET через CDN во время входа.** Скрипт страницы входа может прочитать
  `input.value` и отправить его картинкой на один из 16 разрешённых хостов.
  Закрыть это можно только отказом от загрузки файлов с CDN.
- **POST внутри окна шага не сверяется с `form.action`.** Это цена того, что
  вход в ЦУ вообще заработал.
- **Скрипты вуза исполняются в серверном Chromium.** Изоляция — отдельный
  BrowserContext, а не отдельный процесс ОС на пользователя.
- **Промпты уходят в DeepSeek (Китай).** Это трансграничная передача ПДн по
  152-ФЗ, вопрос помечен «к юристу». Смягчение — минимизация ПДн в промптах.

## Не путать с осознанными ограничениями

Есть **временные** ограничения, которые прямо помечены «подлежит переработке».
Главное — один календарь на вуз и поиск источника по origin, то есть второй
кабинет на том же сайте сейчас подключить нельзя. Владелец уже решил, что
источников может быть сколько угодно (FR-055), план переработки — в
`docs/plan/many-sources.md`. Это долг реализации, а не граница безопасности.
