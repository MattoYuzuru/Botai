# Публичный Web Search

Статус: реализация в `botai.search`, 2026-10-29. Это источник публичных актуальных
сведений; он не доказывает наличие личных данных и не заменяет вход в вуз.
Полная приёмка выпуска и production-smoke фиксируются в [testing.md](testing.md).

## Провайдеры и внутренний интерфейс

`Services.search` предоставляет `SearchService.search()` с общим `SearchBudget` на ход.
Основной провайдер — Exa: `POST https://api.exa.ai/search`, тип `lite`, до пяти результатов,
с highlights. Резервный — настоящий `POST https://api.deepseek.com/v1/tools/search`,
до пяти результатов, без полного содержимого. Chat completions для поиска не используется.
Контракты проверены по [Exa Search](https://exa.ai/docs/reference/search),
[DeepSeek Search guide](https://api-docs.deepseek.com/guides/search/) и
[DeepSeek Search API](https://api-docs.deepseek.com/api/search/).

Результат содержит URL, заголовок, ограниченный фрагмент, провайдера и время получения.
Статусы: `ok`, `empty`, `unavailable`, `rejected`, `budget`; причины отказов сохраняются
отдельно. Пустая публичная выдача означает только отсутствие совпадений в этом запросе.

Чат вызывает `search_public_web` в обычном цикле харнеса и отвечает со ссылками на выдачу.
В CONNECT без известного адреса поиск использует публичное название вуза из контекста
реестра и предлагает кандидаты с указанием провайдера. Пользователь передаёт точную
выбранную ссылку обычным сообщением; выдача сама подключение не создаёт и новых хостов
не разрешает. При недоступном поиске остаётся путь с ручной ссылкой.

## Настройки

| Переменная | Значение по умолчанию | Значение |
|---|---|---|
| `EXA_API_KEY` | пусто | Необязательный серверный ключ Exa |
| `DEEPSEEK_API_KEY` | пусто | Существующий ключ DeepSeek, также для Search API |
| `SEARCH_MODE` | `auto` | `auto`, `off`, `exa`, `deepseek` |
| `SEARCH_DEADLINE_S` | `15` | Общий deadline поиска, 0,1–60 с |
| `SEARCH_MAX_CALLS` | `4` | Попытки API на ход, 1–8; retries тоже расходуют лимит |
| `SEARCH_MAX_COST_USD` | `0.03` | Верхняя оценка расходов на ход, >0 и ≤0,10 USD |
| `SEARCH_COOLDOWN_S` | `60` | Минимальная пауза провайдера после временного отказа, 1–3600 с |

`auto` идёт Exa → DeepSeek; `exa`/`deepseek` закрепляют один провайдер без fallback,
`off` отключает публичный поиск. Отсутствие Exa не ломает запуск: в `auto` пробуется
DeepSeek; отсутствие обоих ключей возвращает `unavailable`.

На сервере несекретные настройки задаются в `/srv/botai/compose.vars`, ключи — только
в `/srv/botai/app.secrets` с правами `0600`. GitHub Actions передаёт секреты по stdin
SSH-процесса, скрипт атомарно обновляет серверный файл, Compose передаёт его контейнерам.
Ключ в GitHub Secret без успешного деплоя ещё не является ключом работающего воркера.
После изменения `SEARCH_MODE` или других настроек примените штатный деплой с
`diagnostics=keep`. Цепочка выпуска описана в [deployment.md](../plan/deployment.md).

## Ошибки, fallback и стоимость

На провайдера — не более двух попыток по ≤5 с в пределах общего deadline. Для сетевого
сбоя, timeout, HTTP 408/425/5xx возможен ограниченный retry с backoff от 0,25 с и
`Retry-After`. При 429 провайдер немедленно уходит на cooldown и в `auto` проверяется
резервный; возвращения к первому провайдеру в этом поиске нет. `Retry-After` может
продлить cooldown до часа. Состояние cooldown живёт в процессе и сбрасывается при рестарте.

| Причина | Поведение |
|---|---|
| Ключ отсутствует | `missing_key`, пропуск провайдера |
| HTTP 401 | `invalid_key`, отключение провайдера до перезапуска после исправления ключа |
| HTTP 403 | `access_denied`, ограничение доступа, в том числе проверка edge/WAF; это не доказательство неверного ключа. Без повторов и обхода, провайдер отключается до перезапуска после действий оператора |
| HTTP 402 | `credits_exhausted`, отдельная причина; пополнить баланс и перезапустить |
| Другой неверный запрос/конфигурация, редирект | `invalid_config`, без пересылки ключа на новый адрес |
| Лимит вызовов, расходов или времени | `budget`, новые запросы не выполняются |
| Оба провайдера недоступны | `unavailable`, актуальные сведения не проверены |

В `auto` после `access_denied` выполняется односторонний fallback к следующему провайдеру.
HTML проверки не передаётся модели и не исполняется; бот не пытается пройти CAPTCHA,
подменить отпечаток или обойти политику провайдера. После запрета обоих провайдеров
поиск остаётся недоступным без повторного переключения между ними.

Бюджет заранее резервирует консервативную оценку каждой попытки: 0,004 USD для Exa,
0,00075 USD для DeepSeek. Это внутренний предохранитель, а не точный счёт провайдера.
Успешные тарифицируемые ответы учитываются в `llm_usage` как `purpose=search`, без query
или содержимого. Общая квота пула учитывает эти расходы. Неоднозначный удалённый timeout
может оказаться платным; он не подтверждает точную сумму в долговременном учёте.

Если результат API уже получен, а запись расходов не завершилась в оставшийся deadline,
валидные результаты возвращаются с `accounting_unconfirmed`. Повторного поиска/fallback
ради записи расходов нет. `accounting=recorded|unconfirmed|not_applicable` показывает
границу доказательства. Это не обещание жёсткого глобального денежного лимита при
отказах БД или неоднозначных ответах провайдера.

## Безопасность и диагностика

Запрос к поиску — короткие публичные слова. Чат не может добавить слова из истории,
закрытого инструмента или страницы: query сверяется с текущим публичным вопросом.
Признаки личного контекста, секретов, ПДн и инъекций приводят к отказу. Ограниченная
длина и консервативные фильтры могут отклонить полезный вопрос; закрытый материал
нельзя вручную добавлять в query ради обхода проверки.

Поиск не получает пароль, cookies, bearer, MFA, личные сообщения или DOM кабинета.
Его HTTP-клиент идёт через EgressProxy с отдельным разрешением только на фиксированный
API-хост; редиректы и cookies не используются. Результаты проходят проверку HTTPS URL,
не становятся сетевыми capabilities и оборачиваются харнесом как недоверенные данные.
Инъекция в выдаче не может расширить запрос или разрешения подключения.

`search.selected`, `search.fallback`, `search.failed`, `search.retry`, `search.result`
и `search.limited` записывают только провайдера, статическую причину, счётчики и задержки.
Query, фрагменты, ключи и исходные сообщения не пишутся. Переключатель и чтение событий —
[диагностика](diagnostics.md).

## Проверка доступности

Операторский smoke использует фиксированный безопасный публичный запрос и тот же
SearchService/EgressProxy. Он выводит только статус, количество, причины и состояние учёта:

```bash
ssh -T mnema 'sudo -n docker exec botai-worker-1 python -m botai.search --provider exa'
ssh -T mnema 'sudo -n docker exec botai-worker-1 python -m botai.search --provider deepseek'
```

Это платные API-запросы: выполнять ограниченно в разрешённом smoke, не в обычном CI.
Локальная проверка 29 октября 2026 получила реальные HTTP 200 от Exa lite и DeepSeek
Search API; она доказывает доступность этих ключей из той локальной среды, но не
передачу ключей в production. Обычные тесты провайдеров, fallback, SSRF/privacy и
prompt injection используют моки без секретов. Проверку production выполняют отдельно
после выкладки проверенного SHA.

В production 29 октября 2026 Exa вернула HTTP 403 с HTML проверки Cloudflare; тот же
ключ в контролируемой локальной среде получил HTTP 200. DeepSeek Search API в production
вернула реальные результаты. Поэтому Exa остаётся первым настроенным провайдером,
но её доступность с сервера не гарантируется: `auto` использует резерв, а причину запрета
Exa оператор выясняет с провайдером штатным способом. Наличие ключа и локальный smoke
не подтверждают доступность API из production.
