# Голосовой ввод: речь в текст

Статус: реализация в `botai.speech` и в поле ввода чата, 2026-10-30. Закрывает FR-046 (микрофон:
диктовка в поле ввода). Основание — запрос владельца от 30.10.2026. Внешний сервис
распознавания — Groq Speech-to-Text; провайдер заменяемый.

## Что видит человек

Микрофон в поле ввода запускает **настоящую запись**. Вместо поля — эквалайзер: столбики
стоят в ряд по центру и растут вверх и вниз от средней линии, высота каждого повторяет громкость
своей части голоса в реальном времени; рядом таймер. Слева «Отменить запись» (×), справа «Готово» (✓).

- «Готово» — запись уходит на распознавание (состояние «Распознаю…»), готовый текст **вставляется в поле
  ввода** (если там уже был текст — через пробел), фокус возвращается в поле. Сообщение само **не
  отправляется**: человек может поправить текст.
- «Отменить запись» — звук выбрасывается, ничего не отправляется и не вставляется.
- Запись длится не больше трёх минут; на пределе она останавливается сама и распознаётся.
- Тихая запись не отправляется: если за всё время уровень ни разу не поднялся над шумом комнаты, страница
  говорит «Ничего не слышно. Проверьте микрофон и попробуйте ещё раз» и не тратит ни запрос, ни лимит (из
  тишины Whisper выдумывает слова). Если уровень узнать нельзя (нет `AudioContext`, он приостановлен браузером),
  запись уходит как есть.
- Микрофон отключили посреди записи — запись прервана с понятным текстом, на сервер ничего не уходит.
  Рекордер, не приславший последний кусок звука за 3 секунды, не подвешивает «Готово»: берётся то, что есть.
- Запись **не** становится вложением и не хранится: ни в Postgres, ни в постоянном файле, ни в журнале (на время
  запроса она в памяти или во временном файле, см. «Безопасность»).
  Обычные аудиофайлы через скрепку остаются вложениями (без расшифровки).
- Нет доступа к микрофону, браузер не умеет записывать звук, сервис выключен или упёрся в лимит —
  человеческий текст в строке `role="alert"`, без системных диалогов. Если браузер не умеет
  `MediaRecorder`, кнопки микрофона нет.

Устройство интерфейса — [стайлгайд](../design/styleguide.md#вложения-и-голос).

## API

`POST /api/v1/speech/transcribe` — `multipart/form-data`, нужна сессия.

| Поле | Значение |
|---|---|
| `audio` | файл записи, до 5 МиБ; контейнер определяется по байтам (webm, ogg, mp4/m4a, wav, mp3, flac), заявленный тип не используется |
| `language` | необязательно, ISO 639-1 из двух строчных букв; по умолчанию `STT_LANGUAGE` (`ru`) |
| `durationMs` | необязательно, длительность, измеренная страницей: первая оценка для суточного лимита и проверка «≤ 3 минут». Реальную длину сервер берёт у провайдера, на заявленную квота не опирается |

Ответ `200`: `{"text": "…"}`. Пустая строка — речи в записи не расслышано (это не ошибка).

| Код | HTTP | Когда |
|---|---|---|
| `stt_unavailable` | 503 | выключено (`STT_PROVIDER=off`, нет ключа, неверные `STT_*`), сервис не ответил или отклонил ключ. Выключенный сервис отвечает **до чтения тела** запроса |
| `stt_rate_limited` | 429 | сервис распознавания просит подождать (`retryAfterS`, если он сообщил) |
| `quota_exceeded` | 429 | лимит пользователя: `scope` = `speech_hour`, `speech_day`, `speech_busy`; `retryAfterS` |
| `validation` | 422 | запись пустая, не аудио, неизвестный язык, сервис не смог её разобрать |
| `validation` | 413 | запись больше 5 МиБ, заявлена длиннее трёх минут (с запасом 10 с) или провайдер измерил её длиннее (текст такой записи не отдаётся, секунды уже списаны) |

Тело запроса ограничено до чтения тем же middleware, что и вложения (`attachments/limits.py`), но своим пределом:
6 МиБ на запись и служебные поля (у файлов — 21 МиБ). По `Content-Length` — `413` сразу, тело без длины считается
и обрывается на пределе. 5 МиБ — это три минуты даже при 128 кбит/с (≈ 3 МБ) с запасом; длинный или тяжёлый файл
не нужен ни одному браузеру и только тратил бы бесплатный тариф. Типы API генерирует `./scripts/gen.sh`
(`apps/web/src/api/schema.gen.ts`).

## Провайдеры

Интерфейс `SpeechToText.transcribe(audio: bytes, *, mime: str, language: str | None) -> Transcription`
(`botai/speech/provider.py`): `Transcription(text, duration_s)` — слова и длина записи, которую измерил сервис
(`None`, если он её не назвал). Провайдер видит только байты записи: ни id студента, ни имени,
ни чата, ни вуза. Сбой — `SpeechFailure(reason, refundable=…)`, где `reason` ∈ `unavailable`, `rate_limited`,
`rejected`, `misconfigured`; сервис превращает его в код API, а `refundable` решает судьбу секунд (ниже). Чтобы добавить провайдера,
реализуйте интерфейс и подключите в `speech.service.build_provider`.

**Groq** (`botai/speech/groq.py`): `POST https://api.groq.com/openai/v1/audio/transcriptions`,
`multipart`: `file`, `model`, `language`, `temperature=0`, `response_format=verbose_json`.
Ключ — заголовком `Authorization: Bearer`, только на этот запрос. Контракт сверен с
[Speech to Text](https://console.groq.com/docs/speech-to-text) и
[Rate Limits](https://console.groq.com/docs/rate-limits).

- Имя файла в запросе строится из найденного контейнера (`recording.webm`): decoder выбирается по расширению.
- Сеть — через EgressProxy с разрешением только на `api.groq.com`, как у публичного поиска; редиректы
  не исполняются, cookies нет. Нового инфраструктурного узла нет.
- Таймауты: попытка ≤ 30 с, общий срок `STT_DEADLINE_S` (45 с). Один повтор через 0,5 с на сетевой сбой,
  таймаут, `408/425/5xx`. `429` не повторяется: код `stt_rate_limited` с `Retry-After` провайдера.
  `400/413/415/422` — «запись не разобрана». `401/402/403/404` и редирект — настройка или доступ:
  человек видит «сейчас недоступно», оператор — причину в диагностике.
- **Тишина.** Whisper склонен сочинять фразу из тишины и шума. Из `verbose_json` отбрасывается сегмент, который
  вероятно тишина (`no_speech_prob > 0.6`) и при этом либо неуверен (`avg_logprob < -1`), либо однообразен
  (`compression_ratio > 2.4`): одно повторение — не повод выбросить честное «да, да, да». Заготовленные фразы,
  которые Whisper выдумывает по-русски («Продолжение следует…», «Субтитры сделал …», «Редактор субтитров …»,
  «Спасибо за просмотр»), отбрасываются, если запись короче 10 с или сегмент тихий (`no_speech_prob > 0.2`):
  в длинной записи с ясной речью те же слова считаются сказанными. Если не осталось ничего — пустой текст.

## Настройки

| Переменная | По умолчанию | Значение |
|---|---|---|
| `GROQ_API_KEY` | пусто | Серверный ключ Groq (`SecretStr`). Не логируется, не отдаётся в ответах, нет во frontend. На сервере лежит в `/srv/botai/speech.secrets`, который читает только контейнер `api` |
| `STT_PROVIDER` | `groq` | `groq` или `off`. Без ключа диктовка выключена и при `groq` |
| `STT_MODEL` | `whisper-large-v3-turbo` | Модель Groq (`whisper-large-v3` точнее, но дороже и медленнее) |
| `STT_LANGUAGE` | `ru` | Язык по умолчанию, две строчные буквы |
| `STT_DEADLINE_S` | `45` | Общий срок запроса к провайдеру с повтором, 5–120 с |
| `STT_REQUESTS_PER_HOUR` | `60` | Записей на пользователя за скользящий час |
| `STT_SECONDS_PER_DAY` | `7200` | Секунд записи на пользователя за скользящие сутки (120 минут), не меньше 180 |

Настройки диктовки читает отдельный класс `SpeechSettings` (`botai/speech/config.py`). **Опечатка в `STT_*`
(`STT_LANGUAGE=RU`, суточный бюджет меньше одной записи, несуществующий провайдер, нечисло) не останавливает API:**
диктовка выключается (`503 stt_unavailable`), а при старте в журнал идёт предупреждение «Dictation is off: invalid
settings …» с именами настроек (значения не пишутся). Остальное приложение стартует как обычно.

Несекретные значения — в `/srv/botai/compose.vars`, ключ — в `/srv/botai/speech.secrets` (`0600`); путь секрета,
деплой и отзыв ключа — [deployment.md](../plan/deployment.md).

## Квота пользователя

Бесплатный тариф Groq общий для всего пула (на момент написания у модели `whisper-large-v3-turbo` —
20 запросов в минуту и 7,2 тыс. секунд аудио в час на организацию), поэтому один студент не должен его
выбрать. `SpeechQuota` считает по скользящим окнам: записи за час, секунды за сутки и не больше двух
запросов одновременно.

- **Секунды списываются по длине, которую измерил провайдер** (`duration` в `verbose_json`), а не по заявленной
  страницей: до ответа резервируется оценка `max(1 с, durationMs, размер / 40 кБ/с)`, после ответа она заменяется
  реальной длиной. Поэтому ложный маленький `durationMs` ничего не даёт: на следующей записи дневной бюджет
  уже учитывает настоящие секунды. Если провайдер измерил запись длиннее 190 с (три минуты и запас), текст не
  отдаётся (`413`), а секунды остаются списанными.
- **Возврат секунд — только при явном отказе провайдера**: 4xx и 429 (запись не принята, ключ или лимит). Таймаут,
  обрыв соединения, 5xx и отмена запроса секунды **не возвращают**: провайдер мог уже обработать запись. Запрос
  в часовом счёте остаётся при любом исходе.
- Превышение — `quota_exceeded` с `retryAfterS`.

Состояние квоты живёт в процессе API: перезапуск его обнуляет, а несколько процессов считали бы
отдельно. Для закрытого пула за одним контейнером API этого достаточно; общий дневной лимит Groq при
этом остаётся на стороне провайдера (`stt_rate_limited`).

## Безопасность

- Аудио живёт на время одного запроса: в памяти, а если больше мегабайта — во временном файле фреймворка (анонимный
  файл в `/tmp`, закрывается вместе с запросом); у контейнера `api` `/tmp` — `tmpfs` (`compose.prod.yaml`), то есть
  в памяти, а не на диске. Не в БД, не в `llm_usage`, не в журнале, не в постоянном файле.
- Выключенный сервис отвечает `503` до чтения тела запроса (`DictationRoute`), а не после того, как принял запись.
- Ключ Groq лежит в отдельном `speech.secrets`, который подключён только к `api`: воркер (Chromium, открывающий
  чужие страницы), прокси и миграция его не видят.
- Ключ не попадает в ответы, заголовки, ошибки провайдера и диагностику; тесты подсовывают провайдеру
  ответ с эхом ключа и проверяют, что он не выходит наружу.
- Диагностика (`speech.transcribed`, `speech.failed`, `speech.retry`, `speech.refused`) пишет провайдера,
  исход, статус, размер в байтах, число знаков и задержку — без текста и звука.
- Распознанный текст попадает в поле ввода, а не в промпт сам по себе: дальше это обычное сообщение
  человека, которое он отправляет сам. К данным вуза и к Vault диктовка доступа не имеет.
- Внешний сервис получает только звук: [security.md](../architecture/security.md), раздел сети.

## Проверки

- Backend (`backend/tests/speech`): провайдер на подменённом HTTP-транспорте (запрос, повтор, 429, 4xx,
  редирект, тишина, заготовленные фразы, `refundable` по статусам), эндпоинт (формат, размер, длина, выключено
  до чтения тела, ошибки, квота и обход ложным `durationMs`, возврат и невозврат секунд, спул во временный
  файл, ключ в ответах и журнале), скользящая квота, неверные `STT_*`. Живых вызовов в CI нет.
- Frontend: Vitest с подменёнными `MediaRecorder` и `AudioContext` (эквалайзер, «Готово», отмена, тишина, фокус,
  отключённый микрофон, зависший рекордер), MSW-хендлер `/speech/transcribe`,
  Playwright `apps/web/e2e/chat-voice.spec.ts` с поддельным микрофоном Chromium.
- Живой smoke выполняется локально и вручную, не более нескольких вызовов (см. ниже); на production
  smoke делает владелец после выкладки.

```bash
# Оператор: проверить ключ из контейнера API на короткой фразе (ключ не печатается)
ssh -T mnema 'sudo -n docker exec botai-api-1 python -m botai.speech --file /tmp/phrase.m4a'
```

Результат живого прогона этой реализации — в отчёте PR; он не доказывает передачу ключа в production.
