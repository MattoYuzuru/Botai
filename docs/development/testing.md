# Тесты и проверки

Статус: **действующий порядок проверок v4**, обновлено 2026-10-31 пивотом
«свободный harness». Заменяет прежнюю систему уровней. Основание —
[решения владельца](../v4/06-decisions.md) (D-003, D-007, D-009, D-010, D-014).
Архитектура проверок — [04-benchmark.md](../v4/04-benchmark.md).

Принцип: **живой вуз важнее фикстур, но CI не ходит в настоящий вуз.** Успех на
`fakeuni` не доказывает подключение настоящего вуза; живой прогон не заменяет
юнит-тесты. Секреты никогда не появляются в репозитории, выводе и артефактах.

## Уровни

| Уровень | Что проверяет | Сеть | Ключ модели | Где | Кто |
|---|---|---|---|---|---|
| **L0** — юнит | Чистая логика: схемы, нормализация, склейка, lint playbook, дизайн-токены (`pytest`, `vitest`) | Нет | Нет | Локально, CI | Все |
| **L1** — интеграция на фикстурах | API + Postgres + worker + Chromium против `fakeuni` на loopback; LLM — `ScriptedLlm` | Только loopback | Нет (`LLM_PROVIDER=mock`) | Локально, CI | Все |
| **L2** — живая модель | Агент действительно справляется: черновик/починка playbook, чтение SPA, ответ по данным, действия | API модели | `DEEPSEEK_API_KEY` / Claude | Локально | Владелец или агент по поручению |
| **L3** — живой вуз | Настоящий вход, сессия, API, динамическая страница, действие, свой парсер, RAG-ответ | Вуз + модель | Да | Локально (`bench/live/` — примитивы, `bench/v4/` — агент) и на production | Агент-оператор + владелец |
| **L4** — сравнение | Те же задачи решает внешний harness (Codex/Claude Code/скрипт), результаты сравнимы | Да | Да | Локально | Владелец/агент |

Правила:

- Новое поведение закрывается тестом L0 или L1. PR без теста не мержится.
- L2/L3 не заменяют L0/L1 и наоборот.
- Живой прогон L3 фиксируется: дата, SHA, сценарий, успех/барьер, стоимость,
  путь к артефактам. Без этого он не доказательство.
- CI не получает ключей моделей, кредов вузов и живых сессий.
- Тесты создают и удаляют отдельные БД; retained-тома не сбрасываются.

## Секреты и артефакты

- **Первичные секреты** (пароль вуза, код MFA, ключ-ссылка календаря) не
  встречаются в открытом виде ни в БД (только шифртекст Vault), ни в логах, ни в
  сообщениях, ни в промптах модели, ни в коммитах. Проверяется grep'ом в CI.
- **Сессия** (cookie, bearer, storage) — рабочий материал агента: может храниться
  в Vault, попадать в артефакты L3 и в браузерный контекст. В промпт модели по
  умолчанию не подставляется; если задача требует — допустимо.
- Сырые артефакты живых прогонов (HAR, скриншоты, storage state) — только вне
  репозитория: `~/.local/state/botai-v4-bench/<дата>/`, права `0700`.
- В публичный репозиторий и docs попадают только санитизированные сводки:
  счётчики, коды, обезличенные фрагменты. Пароль-поля вычищаются из HAR и логов
  до сохранения.
- Креды для L3 выдаёт secret broker: macOS Keychain (`botai.live.*`) или файл
  `0600`; значения не печатаются и не попадают в аргументы процессов, доступные
  агенту в открытом виде.

## Команды

```bash
make db            # Postgres для разработки (127.0.0.1:55432, образ pgvector/pgvector:pg17)
make check         # ruff, ruff format, pyright strict, pytest; Biome, tsc, vitest; make gen
make test-backend
make test-web

# L2: живая модель (ключ из .env, не печатается)
cd backend && BOTAI_LIVE_LLM=1 BOTAI_ENV_FILE=../.env uv run --frozen pytest -q -m live_llm

# агентский бенчмарк L2 (v3-путь)
make bench SCENARIO=B4 ARGS="--models flash --profiles low,high --repeats 3"

# v4-песочница кода: образ нужен для docker-gated тестов и контейнерного executor'а
docker build -f ops/docker/sandbox.Dockerfile -t botai-sandbox:test .
cd backend && BOTAI_SANDBOX_IMAGE=botai-sandbox:test \
  uv run --frozen pytest tests/agent/v4/test_executor_container.py -q

# v4-агент (тот же wiring, что у job AGENT): L2 на fakeuni ($0) и L3 на живом вузе
backend/.venv/bin/python -m bench.v4.run_agent --scenario l2-fakeuni
backend/.venv/bin/python -m bench.v4.run_agent --scenario live-hse   # BOTAI_LIVE_LLM=1, Keychain

# L3: живой вуз (примитивы harness: креды из Keychain, артефакты вне репозитория)
python -m bench.live.run --scenario login
python -m bench.live.run --scenario cu-tasks
python -m bench.live.run --scenario hse-schedule

# миграции: upgrade/downgrade проверяются на одноразовой БД (тесты делают это сами)
make migrate
```

Точные сценарии, флаги и ожидаемые результаты — [04-benchmark.md](../v4/04-benchmark.md).

## Ключи моделей

- `DEEPSEEK_API_KEY` — в `.env` (в `.gitignore`) или в Keychain; шаблон без
  значений — `.env.example`.
- Claude/Anthropic — отдельный ключ в `.env` или Keychain; используется
  профилем `agent` для сложных задач.
- Ключ никогда не печатается: ни в логах, ни в выводе тестов, ни в описании PR,
  ни в сообщениях агента. Для проверки наличия — маскированный вывод.
- L0/L1 ключ не читают. L2 включается только явно (`BOTAI_LIVE_LLM=1`) и имеет
  мягкий потолок стоимости (`BOTAI_LIVE_LLM_BUDGET_USD`).
- Если ключ попал в коммит/лог/чат — отозвать в кабинете провайдера.

## Мок модели

`LLM_PROVIDER=mock` подключает `ScriptedLlm`: ответы из записанных фикстур по
хешу запроса. Мок умеет имитировать ошибки провайдера (таймаут, 429, 5xx, обрыв
стрима, квоту). Нет фикстуры — падение с понятной ошибкой, а не пустой ответ.
Новые фикстуры записываются L2-прогоном, проверяются глазами, секретов и личных
данных в них быть не может.

## Фикстурный стенд `fakeuni` (L1)

Синтетический вуз `backend/tests/fakeuni/` (FastAPI) на loopback: Keycloak-подобный
вход (включая многошаговую JS-форму без `action`), SMS/MFA, экран капчи, протухание
сессии, редирект на чужой хост, страница с инъекцией, смена формата ответа, SPA-кабинет
(faq, bearer из localStorage, попытки POST/чужого хоста/WebSocket), LMS с правилами
повторения и заданиями, iCal, CDN-ассеты, sliding window дат. Всё в нём синтетическое:
ничего от настоящих вузов, никаких реальных адресов и селекторов.

Важнейшие группы L1:

- вход и сессия: пароль, MFA, капча (человек в цикле при необходимости), повторный вход,
  восстановление после рестарта, отсутствие первичных секретов вне Vault;
- браузер: динамическая SPA, отложенные запросы, смена вкладок, клики, ввод,
  перехват запросов, cookie/storage, HAR, загрузки;
- источники: создание/обновление/починка playbook, N источников на одном хосте,
  несколько календарей, несколько видов у источника, склейка и приоритеты;
- агент: инструменты, цикл, трассы, восстановление задачи, мягкие лимиты;
- действия: POST/формы по политике `auto`/`ask`/`never`, журнал, идемпотентность;
- RAG: индексация артефактов, ответ со ссылкой, свежесть;
- сквозной e2e: API + очередь + worker + Chromium + Vault + агент.

## Сквозной тест (L1, `backend/tests/e2e/`)

Один процесс, настоящие компоненты; подменены только вуз (`fakeuni` по HTTPS на
loopback) и модель (`ScriptedLlm`). Студента играет `Student`: идёт по SSE и
отвечает на блоки через `POST /api/v1/jobs/{id}/answers`. Сценарии: подключение,
вход, MFA, review данных, повторный вход, sync, починка, второй студент, отмена,
недоступный вуз, действия. Проверка C1 (обновлённая): первичные секреты не
встречаются ни в одной таблице, логе, событии и запросе к модели; в `secrets`
только шифртекст.

## L3: живой бенчмарк

- Примитивы: [`bench/live/`](../../bench/live/) — вход, сессия, API discovery, динамическая
  страница, метрики, санитизированные артефакты; дизайн — [04-benchmark.md](../v4/04-benchmark.md).
- Агент v4: [`bench/v4/`](../../bench/v4/) — строит настоящий `build_agent_wiring`, реальная
  модель и Chromium, креды только через `secret_request`/Vault; L2 — `--scenario l2-fakeuni`
  (mock-модель, $0), L3 — `--scenario live-hse` (Keychain-креды, живой вход/SSO/расписание).
  В репозиторий едет санитизированная сводка, сырое — вне него.
- Креды — из secret broker; первичные секреты не попадают в промпт/логи/артефакты; вывод
  инструментов маскируется `SecretBroker.mask` (включая `code_exec`).
- Сценарии: login, session extraction, API discovery, dynamic page («Actual Student Tasks»),
  action/write, code parser, RAG answer, repair.
- Метрики: успех, время, шаги, токены/стоимость, полнота данных, найденные эндпоинты,
  барьеры (капча, 403, challenge), что помогло.
- Результаты — `bench/results/live-<дата>.json` + `docs/v4/_evidence/<дата>/` (санитизировано)
  и раздел в [04-benchmark.md](../v4/04-benchmark.md); сырые — вне репозитория.

## CI и приёмка релиза

CI (GitHub Actions) выполняет L0/L1 и сборки; живых ключей и кредов не получает.
В backend-job собирается образ `botai-sandbox:ci` и docker-gated тесты
`ContainerExecutor` реально запускаются (не skip); Postgres в CI — `pgvector/pgvector:pg17`,
миграции с `CREATE EXTENSION vector` проходят. Deploy-workflow собирает и app-, и
sandbox-образ и тегирует их одним commit SHA; `remote-deploy.sh` тянет оба, сверяет
`org.opencontainers.image.revision`, поднимает Postgres до миграций и убирает остатки
sandbox-контейнеров. Приёмка выпуска: зелёный CI на полном SHA → миграции на копии →
deploy того же SHA → health/`revision` у всех сервисов → live smoke и L3-сценарий → отчёт.

## Что требуется от PR

- Назван пункт [плана](../v4/05-implementation-plan.md) или решение
  [06-decisions.md](../v4/06-decisions.md).
- Новое поведение закрыто тестом; если только мок — сказано прямо.
- Перечислено, что должен проверить владелец на L3.
- Нет секретов, персональных данных и живых адресов с ключами.
- `make check` зелёный; сгенерированные файлы не расходятся.

## Границы доказательств

- `fakeuni` — синтетика; он не доказывает поведение настоящего вуза.
- L2 — качество модели на известных сценариях, не на живом сайте.
- L3-прогон доказывает только проверенные сценарии на дату, аккаунт и SHA;
  скриншоты и трассы могут устареть, их нужно привязывать к SHA.
- Капча/антибот могут измениться в любой момент; барьеры фиксируются датой.
- Ответ агента без источника не считается подтверждённым.
