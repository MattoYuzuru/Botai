# Варя в Botai

Ворона Варя — пиксельный маскот ВШЭ из `doodle_vibe/mascot`. В Botai она переиспользуется целиком:
тот же спрайт, те же анимации, тот же API. Этот документ описывает, как она подключена, какими
состояниями управляется, где живёт и чего не делает никогда.

Визуальные токены, компоненты и правила движения — [styleguide.md](styleguide.md). Варя не вводит
своих цветов интерфейса и не отменяет ни одного правила оттуда.

## 1. Контракт переиспользования

Renderer **копируется один раз как снимок**: `mascot/varya.js`, `mascot/sprites/` и
`mascot/tools/export.mjs` из `doodle_vibe` переносятся в `packages/design/mascot/vendor/` вместе с
`README.md` источника и записью происхождения в `docs/design/vendor.md` (репозиторий, коммит, дата).
Botai и `doodle_vibe` — **раздельные проекты**: из `doodle_vibe` берётся только Варя, обратной
синхронизации нет. После копирования Botai владеет своей копией и сам добавляет в неё ситуации.
Файл не переписывается под React и не разбирается на модули — так проще сравнить с источником,
если Варю когда-нибудь захочется обновить вручную.

### Что остаётся без изменений

| API | Использование в Botai |
|---|---|
| `Varya.mount(el, { theme, situation, onSay, onAnim })` | Единственный способ показать живую Варю. Монтируется в `useEffect`, `destroy()` — при размонтировании |
| `varya.setSituation(id)` | Смена ситуации по состоянию продукта |
| `varya.setTheme('day' \| 'orig' \| 'pj')` | `pj` — только ночная ситуация; тема интерфейса на `theme` не влияет |
| `varya.react()` | Разовая реакция (подключение завершено, работа сдана) |
| `varya.destroy()` | Обязателен при уходе с экрана и смене пространства |
| `Varya.svg({ situation, theme, eyes, props, size })` | Статичная картинка: пустые состояния, иконка вуза, витрина, сезонный превью |
| `Varya.SITUATIONS` | Чтение списка id и поз для витрины; реплики Botai берёт из своего реестра (§6) |

Стили анимаций renderer добавляет на страницу сам один раз (`<style id="varya-css">`), все классы
начинаются с `varya` — конфликта с токенами нет. `prefers-reduced-motion` renderer уже уважает;
Botai дополнительно гасит его своим флагом (§2).

### Что Botai может добавить

- **Новые ситуации** — объектом в `SITUATIONS` своей копии (реакция, глаза по тактам, поза для
  превью) и пересборкой спрайтов `node packages/design/mascot/vendor/tools/export.mjs`. Для Botai
  добавляются: `sync`, `think`, `overdue`, `offline`, `reauth`, `error`, `idle`, `perch` (сидит на
  кромке поля ввода, §4), `wave` (машет крылом).
- **Свой реестр реплик** (§6) поверх ситуаций: реплики собираются из настоящих данных, поэтому
  живут в Botai, а не в renderer.
- **Сезонные образы** — через `props`/`theme` и реестр §7.
- **Оболочку** `MascotStage`: размер, подпись, одно действие, `aria-hidden` у картинки.

### Чего renderer не делает никогда

- Не ходит в сеть, не читает API, не знает про `fetch`, `localStorage` и stores.
- Не хранит учебные данные: он получает **готовый объект состояния** и размер, больше ничего.
  Ему не передают учётные данные, cookies, токены, профиль, ответы сервера и историю чата.
- Не вычисляет срочность и даты: пороги и `effectiveDue` живут в `packages/shared` (модуль `urgency`, тот же,
  что у `DeadlineItem`).
- Не выполняет действий: нажатие на карточку маскота отдаёт наверх типизированный `intent`
  (`open-deadline`, `open-chat`, `open-source`, `reauth`, `retry`, `connect`), разрешает его
  frontend.
- Не перекрывает поле ввода, нижнюю панель, CTA, ссылки и метки источника; не перехватывает
  прокрутку невидимым слоем.
- Повреждённый или отсутствующий ресурс даёт базовую Варю; данные и экраны от картинки не зависят.

## 2. Модель состояния

Состояние вычисляет **чистая функция** `resolveMascot(context): MascotPresentation` в
`packages/design/mascot/resolve.ts`: без запросов, без чтения DOM и stores, без скрытого `Date.now()` и без
случайности. Одинаковый вход и `nowMs` всегда дают одинаковый выход — это и есть тест.

```ts
type MascotContext = {
  spaceId: string;                  // активное пространство вуза
  nowMs: number;                    // те же часы, что ушли в UI
  timeZone: string;                 // часовой пояс пространства
  screen: 'chat' | 'schedule' | 'deadlines' | 'progress' | 'other';
  availability: 'ready' | 'unknown' | 'empty' | 'offline' | 'reauth' | 'error';
  activity: 'idle' | 'connecting' | 'syncing' | 'thinking';
  snapshot: {
    spaceId: string; updatedAt: number; stale: boolean;
    nextClass: { startMs: number; title: string; room?: string } | null;
    deadlines: readonly { id: string; title: string; dueMs: number | null; done: boolean }[];
  } | null;
  recentEvent: { id: string; spaceId: string; kind: 'deadline-done' | 'space-connected'; at: number } | null;
  acknowledgedEventIds: readonly string[];
  preferences: { seasonal: boolean; motion: 'system' | 'calm' };
  reducedMotion: boolean;
  lite: boolean;                    // слабая сеть/устройство, экономия
  visible: boolean;                 // document.visibilityState === 'visible'
  keyboardOpen: boolean;
};

type MascotPresentation = {
  situation: string;                // id ситуации renderer
  theme: 'day' | 'orig' | 'pj';
  motion: 'animated' | 'static';
  line: string | null;              // из реестра §6, уже подставленные числа
  badge: { tone: 'warning' | 'danger' | 'neutral'; text: string } | null;
  intent: MascotIntent | null;
  skin: string | null;              // сезонный образ, §7
  visible: boolean;                 // показывать ли маскота вообще
};
```

Снимок или событие с `spaceId`, не равным активному, отбрасывается. При смене пространства прежние
реплика, бейдж и реакция снимаются сразу, до нового снимка состояние — `unknown`.

### Приоритет

Сверху вниз, первое совпадение выигрывает. Срочность при ошибке или операции остаётся
дополнительным бейджем, но ситуацию не меняет.

| № | Условие | Ситуация | Движение | Действие (`intent`) |
|---|---|---|---|---|
| 1 | `availability: 'reauth'` (код `source_auth_required`) | `reauth` | сдержанное | «Войти снова» → `reauth` |
| 2 | `availability: 'offline'` | `offline` | статично | — (повтор сам при сети) |
| 3 | `availability: 'error'` | `error` | статично | «Повторить» → `retry` |
| 4 | `activity: 'connecting'` | `connect` | бег на месте | «Открыть ход» → `open-progress` |
| 5 | `activity: 'syncing'` | `sync` | бег на месте | «Открыть ход» → `open-progress` |
| 6 | `activity: 'thinking'` | `think` | наклон головы, пузыри | «К чату» → `open-chat` |
| 7 | `recentEvent` не подтверждён (`id` ∉ `acknowledgedEventIds`), моложе 60 с | `done` | одна реакция ≤ 1.5 с | «Дальше» → `open-deadline` |
| 8 | Есть открытый дедлайн с `dueMs ≤ now` | `overdue` | статичный знак | «Открыть работу» → `open-deadline` |
| 9 | Открытый дедлайн, до срока ≤ 24 ч | `deadline` | тёплое свечение | «Открыть срочную» → `open-deadline` |
| 10 | Открытый дедлайн, 24 ч < срок ≤ 72 ч | `tip` | спокойное | «Открыть работу» → `open-deadline` |
| 11 | `nextClass` начинается в пределах 60 мин | `class` | будильник | «Открыть расписание» → `open-schedule` |
| 12 | `availability: 'empty'` | `connect` | статично | «Подключить вуз» → `connect` |
| 13 | Локальное время 23:00–05:00 в `timeZone` | `night` (`theme: 'pj'`) | сдержанное | — |
| 14 | Всё сдано, снимок свежий | `done` (поза, без реакции) | статично | — |
| 15 | Иначе | `idle` | easter egg (§4) | — |

Тиры срочности (72 ч / 24 ч / 0 / просрочено) считает `urgency` из `packages/shared`. Срок `null` или
невалидный — ситуация `tip` **без** обратного отсчёта и без выдуманного срока. Несколько срочных
работ дают одну выбранную (ближайший срок, при равенстве — стабильно по `id`) и бейдж со счётчиком
«и ещё 2», а не несколько маскотов.

### Движение и остановка

`motion: 'static'` принудительно, если `reducedMotion`, `preferences.motion === 'calm'`, `lite`
или `visible === false`. Статичный вариант сохраняет весь смысл: поза, бейдж и реплика те же,
исчезает только петля. Один анимированный маскот на экран — больше одного запрещено. При возврате
вкладки старая реакция не проигрывается заново (`acknowledgedEventIds`). Реакция на сдачу
дедуплицируется по `spaceId` + `eventId`; первый снимок с уже сданными работами реакций не создаёт.

## 3. ProgressWall

Экран длинной работы агента: изучение нового вуза, полная синхронизация. Открывается, когда работа
заведомо дольше ~5 с, и закрывается только по итогу или по действию пользователя. Компонент — `ProgressWall`, живёт в `apps/web/src/widgets/progress-wall`.

### Что на экране, сверху вниз

| Блок | Содержимое | Правила |
|---|---|---|
| Шапка | Название работы («Подключаю ВШЭ»), вуз, `IconButton` «Свернуть» | Работа продолжается в фоне после свёртывания; её состояние видно в шапке экранов |
| Стена и рельс | `ProgressRail`: горизонтальный рельс по низу блока, Варя бежит по нему слева направо | Рельс — это **стадии**, а не проценты: он разделён на засечки по числу известных стадий, пройденные закрашены `accent`, текущая пульсирует |
| Стадия | `type-heading` — название текущей стадии («Читаю список курсов») | Берётся из `event: status` потока `GET /jobs/{id}/events` (`{state, stage, startedAt}`), не придумывается |
| Время | «Идёт 1 мин 12 с» (`tabular-nums`, обновление раз в секунду) | Всегда настоящее прошедшее время |
| Осталось | Либо «Осталось примерно 2 мин» (если сервер дал оценку), либо «Сколько осталось — пока неизвестно» | **Никакого придуманного процента и ETA.** `etaKnown: false` → импульс без числа |
| Поток рассуждения | `ThinkingStream` из блоков `thinking` (`event: block`, идемпотентны по `id`): лог шагов, новый шаг добавляется снизу, завершённый — галочка, упавший — иконка и текст `danger-fg` и причина | Развёрнут на `ProgressWall` по умолчанию; авто-прокрутка к последнему шагу, но останавливается, если пользователь прокрутил вверх |
| Итог | Блок `summary` (`event: done`): что подключено, что нет, свежесть каждого источника; `Button primary` «Готово» | Экран не исчезает сам: итог нужно прочитать |

Варя бежит по рельсу: координата — **номер завершённой стадии**, а не поддельный процент. Пока
стадия идёт, она бежит на месте. Если число стадий неизвестно, рельс без засечек, Варя бежит на
месте, и это подписано «Сколько осталось — пока неизвестно». При `motion: 'static'` Варя стоит на
позиции последней завершённой стадии, рельс — ровная заливка, время и стадия продолжают обновляться
текстом.

### Когда работе нужен пользователь

Работа встаёт на паузу и говорит об этом словами, а не только анимацией. Варя переходит в `tip`
(ждёт), рельс — статичен, в `ThinkingStream` последний шаг получает состояние `waiting`.

| Нужно | Что появляется | Поведение |
|---|---|---|
| Уточняющий вопрос (`choice`, `input`) | Карточка вопроса под стадией: текст + `RadioGroup`/`Checkbox`/`Input` + «Ответить» | Подпись «Жду ответа»; при `required: true` сказано, что без ответа работа не продолжится. У необязательного есть «Не знаю» / «Пропустить». Таймаута у ожидания нет |
| Вход в ЛК вуза (`login`) | Карточка «Нужно войти в ЛК ВШЭ» + `Button primary` «Войти» → `LoginSessionView` | Вход делает человек; капча и MFA (`needs`) — сигнал «нужен человек», а не задача обхода. Пароль и кадры не попадают ни в поток, ни в лог, ни в реплику |
| Согласие на запись (`approval`) | `ApprovalCard`: метод, хост, поля и вуз, кнопки «Подтвердить» / «Не делать» | Подтверждение одноразовое и истекает (`expiresAt` виден). Автоподтверждения по таймеру нет; отказ продолжает работу без этого шага |
| Сбой стадии (`event: error`) | Шаг `failed` + причина человеческим языком; ниже «Повторить стадию» и «Пропустить» | Остальной прогресс сохраняется, итог покажет, что не подключилось. `egress_blocked` показывает хост и спрашивает пользователя, `source_auth_required` ведёт на вход |

Любой из этих блоков объявляется один раз через `aria-live="polite"`; стадии и секунды не
объявляются. Сворачивание экрана оставляет вопрос доступным: в шапке — `Badge tone="warning"`
«Нужен ответ».

## 4. Варя в чате

Ориентир — скриншот владельца: в Claude пиксельный персонаж **сидит на верхней кромке поля ввода**
справа, как птица на жёрдочке. Варя в чате ведёт себя так же. У неё два места: насест (всегда) и
сцена (только в пустом чате).

### 4.1 Насест — на кромке поля ввода

| Правило | Значение |
|---|---|
| Где | Верхняя кромка `ChatComposer`, справа, отступ 16 px от правого края. Лапы стоят на линии рамки, тело — **снаружи** поля, над ним |
| Размер | 36 px (спрайт 32×32 с обводкой); на 430 px и шире — 40 px |
| Когда | В чате всегда, в пустом и непустом. На других экранах насеста нет |
| Что не перекрывает | Текст ввода, плейсхолдер, кнопки «Отправить» и «Прикрепить», последнее сообщение. Лента сообщений получает нижний отступ, равный выступу Вари над кромкой (≈ 24 px) — последнее сообщение не уходит под неё |
| Слой | Часть стека `ChatComposer` (z 20), рисуется после поля; `pointer-events` только у самого спрайта |
| Поведение | `perch` в покое: моргает, иногда поворачивает голову (раз в 8–14 с). Агент отвечает → `think` (наклон головы, точки). Ответ пришёл → один кивок. Идёт работа агента → `sync` на месте. Нужен ответ пользователя → `tip` |
| Клавиатура | Поле поднимается вместе с клавиатурой, Варя едет вместе с ним; анимации на это время выключены, пузырь скрыт |

### 4.2 Сцена — пустой чат

Пока в чате нет сообщений, у Вари есть «пол» — полоса высотой 120 px над полем ввода.

| Правило | Значение |
|---|---|
| Размер | 96 px на 320–389 px, 120 px на 390 px и шире; высота сцены фиксирована, раскладка не прыгает |
| Цикл | Пауза 6–10 с → одно действие 1.5–2.5 с: пройтись влево-вправо, клюнуть пол, встряхнуться, посмотреть вверх, помахать крылом. Порядок — из `nowMs`, детерминированно, без `Math.random()` |
| Первое сообщение | Варя прыгает со сцены на насест одним движением ≤ `duration-slow` (280 ms) и дальше живёт на насесте. При `motion: 'static'` — мгновенная смена без перелёта |
| Подсказки | Три подсказки-вопроса (`EmptyState`) стоят выше сцены и строятся из настоящих данных («Какая следующая пара?», «Что сдавать на неделе?»). Варя их не перекрывает |
| Слой | z 15 — ниже поля ввода и `TabBar` |

### 4.3 Варя говорит

Варя разговаривает короткими пузырями над насестом или над сценой — как персонаж, а не как агент.

| Когда | Что говорит | Источник |
|---|---|---|
| Открыт пустой чат | Одна фраза-приветствие из данных: «Сегодня 3 пары, первая в 9:30» | Снимок (§6), один раз за открытие |
| Агент работает | Текущая стадия коротко: «Ищу в ЛК ВШЭ» | `event: status`, не чаще раза в 4 с |
| Нажатие на Варю | Следующая реплика её ситуации из §6 | Реестр реплик |
| Три быстрых нажатия | Машет крылом (`wave`), один раз за сессию | Пасхалка |

- Пузырь: до 48 знаков, `type-caption`, `surface-raised` + `shadow-md`, хвостик к клюву; исчезает
  через 6 с или по нажатию. Одновременно — один пузырь.
- Пузырь **не заменяет** ответ агента: ответ — всегда `ChatMessage` с источниками. Варя не
  отвечает на вопросы, не выдаёт фактов, которых нет в UI, и не говорит, пока пользователь
  печатает.
- Пузырь `aria-hidden`: всё, что в нём сказано, уже есть текстом на экране (стадия в
  `ThinkingStream`, пары на «Сегодня»).

### 4.4 Тишина

`reducedMotion`, `calm`, `lite` → статичная поза на насесте, сцена без цикла, перелёта нет; пузыри
остаются (это текст). `visible: false` (скрытая вкладка, свёрнутое приложение) → всё остановлено,
при возврате продолжается с текущей позы, без догоняющих кадров.

На остальных экранах Варя появляется только по §2 и только одна на экран.

## 5. Доступность

- Спрайт декоративен: контейнер — `aria-hidden="true"`, из порядка обхода исключён, фокус не
  принимает.
- **Каждый смысл, который несёт Варя, существует текстом.** Поза `deadline` → `Badge` «Осталось
  5 ч» и строка срока; `reauth` → полоса «Нужно снова войти в ЛК ВШЭ» и кнопка; `sync` → стадия и
  прошедшее время; `done` → «Работа сдана». Если убрать картинку, экран остаётся понятным — это
  проверяется тестом (рендер с `visible: false`).
- Действие маскота дублируется обычной кнопкой `MascotStage` с подписью; нажатие по самому спрайту
  не единственный способ.
- `aria-live="polite"` — только итоги и смена стадии; обратный отсчёт, секунды и кадры анимации не
  объявляются.
- Вспышек и резких перемен яркости нет. Декоративное движение останавливается настройкой
  «спокойный маскот» в настройках приложения, независимой от сезонности.
- Контраст реплики и бейджа — по правилам [styleguide.md](styleguide.md) §2, на итоговом фоне.

## 6. Реплики

Реплики — в `packages/design/mascot/lines.ts`: по 2–3 варианта на ситуацию, выбор детерминирован
(`nowMs` → индекс). Числа и названия подставляются **только** из снимка; шаблон без данных не
показывается — вместо него берётся вариант без числа.

| Ситуация | Реплика (шаблон) | Подстановка |
|---|---|---|
| `idle` (пустой чат) | «Сегодня {pairs}, первая в {time}» / «Пар сегодня нет» / «Спроси меня про дедлайны» | `pairs` = `pluralRu(n, ['пара', 'пары', 'пар'])` из снимка; без снимка — третий вариант |
| `perch` | — (на насесте молчит, пока её не нажали) | — |
| `connect` | «Готова изучить твой вуз» / «Подключим — и всё будет в одном месте» | — |
| `connect` (в работе) | «Читаю {source}» | Название раздела из стадии |
| `sync` | «Обновляю {space}, идёт {elapsed}» | Название вуза, прошедшее время |
| `think` | «Ищу в {space}» | Активный вуз; обещаний результата нет |
| `class` | «{title} в {time}, {room}» | Из `nextClass`; без аудитории — вариант «{title} в {time}» |
| `tip` | «До «{title}» — {left}» | Срок > 24 ч |
| `deadline` | «{title}: осталось {left}» | Срок ≤ 24 ч, `left` из `urgency` |
| `overdue` | «Срок «{title}» прошёл {ago}» | Без упрёков и восклицаний |
| `done` | «{title} сдано» / «Пока всё сдано» | Второй вариант — когда открытых работ нет |
| `night` | «{count} — на утро?» | Число открытых работ; при 0 — «Уже поздно» |
| `offline` | «Нет сети. Это снимок от {updatedAt}» | Время снимка |
| `reauth` | «{space} просит войти снова» | Название вуза |
| `error` | «Не получилось обновить {space}» | Название вуза |
| `skips` | не используется в MVP | Данных о пропусках Botai пока не собирает |

Правила:

- **Никаких придуманных чисел.** Нет данных — нет числа. Проценты готовности, вероятности,
  «примерно столько-то заданий», выдуманные аудитории и даты запрещены; это ловит тест реплик
  (каждый шаблон обязан объявить требуемые поля снимка).
- Реплика — одна строка до 48 знаков, без восклицаний и эмодзи. Варя обращается на «ты» — она
  персонаж; интерфейс остаётся безличным и на «вы» (решение ждёт [Q31](../../QUESTIONS.md)).
- Реплика не заменяет текст интерфейса: срок, вуз и действие остаются в компонентах.
- Реплика не содержит персональных данных третьих лиц (ФИО преподавателя — только если оно уже
  показано в расписании рядом) и никогда — учётных данных.

## 7. Сезонные образы

Сезонный образ — **декоративный слой** поверх выбранной позы. Он сочетается с любой ситуацией и
никогда не перекрывает срок, статус источника и ошибку. «Варя у дедлайна» — состояние, а не
календарное событие.

Реестр — `packages/design/mascot/events.ts`, данные, не код:

```ts
type MascotEvent = {
  eventId: string;
  from: { month: number; day: number };   // включительно, 00:00
  to:   { month: number; day: number };   // исключительно, 00:00
  timeZone: string;                        // часовой пояс пространства
  priority: number;                        // больше — важнее
  skinId: string;                          // props/theme renderer
  staticFallback: string;                  // спрайт для motion: 'static'
};
```

| eventId | Окно | Образ | priority |
|---|---|---|---|
| `new-year` | 20 декабря 00:00 → 11 января 00:00 | Колпак и небольшая искра | 100 |
| `session-winter` | 10 января 00:00 → 1 февраля 00:00 | Кружка (повторное использование `night`) | 50 |
| `session-summer` | 1 июня 00:00 → 1 июля 00:00 | Кружка | 50 |
| `knowledge-day` | 1 сентября 00:00 → 2 сентября 00:00 | Листок в клюве | 60 |

Правила календаря (проверяемые):

- Окно задаётся в часовом поясе активного пространства; переход через год (декабрь → январь)
  обрабатывается явно. `from` включительно, `to` исключительно.
- Пересечение окон → максимальный `priority`, при равенстве — стабильно по `eventId`.
  Два аксессуара в один слот (голова) не накладываются: выбирается один.
- `preferences.seasonal: false` отключает все образы, не затрагивая срочность, реплику и действие.
  Настройка движения независима от сезонности.
- После окна возвращается базовый образ; срочность при этом не сбрасывается.
- Любой образ просматривается на фикстуре с заданными `nowMs` и `timeZone` — ждать нужного месяца
  не нужно. Произвольные JS-сниппеты и загрузка правил по сети форматом реестра не являются.
- Бюджет одного сезонного набора — ≤ 250 KiB сжатых ресурсов с отложенной загрузкой. Спрайты
  собираются в браузере кодом, сетью не передаются.

## 8. Проверки

Детерминированные фикстуры в `/styleguide#mascot` (синтетические данные, вход в вуз не нужен):

| Фикстура | Ожидаемый результат |
|---|---|
| `urgent` (срок через 5 ч) | Поза `deadline`, бейдж «Осталось 5 ч», действие «Открыть срочную» |
| `urgent` + `reducedMotion` | То же статично, та же информация и действие |
| `urgent` + `reauth` | Первична просьба войти снова; старый срок помечен устаревшим; сезонного слоя нет |
| `overdue` | «Просрочено», без упрёков, бесконечной тревоги и реакции |
| `due-unknown` | Поза `tip`, «Срок не указан», обратного отсчёта нет |
| `done-once` | Одна реакция ≤ 1.5 с; после reload не повторяется |
| `no-data` | `connect` + «Подключить вуз»; не выглядит как «всё сдано» |
| `stale-after-failed-sync` | Старые данные помечены устаревшими; «всё сдано» не показывается |
| `space-switch` ВШЭ → ЦУ | Прежние реплика, бейдж и реакция убраны сразу; состояние `unknown` до нового снимка |
| `thinking` | `think`, «Ищу в …», без обещания результата |
| `progress-wall` без ETA | «Сколько осталось — пока неизвестно», процента нет |
| `progress-wall` с вопросом | Работа на паузе, «Жду ответа», вопрос доступен и после сворачивания |
| `new-year` + `urgent` | Колпак и срок одновременно; читаемость срока не пострадала |
| `19 декабря 23:59 → 20 декабря 00:00` | Смена базового образа на новогодний по `timeZone` пространства |
| `10 января → 11 января 00:00` | Возврат базового образа, срочность не сброшена |
| `seasonal: false` | Базовая Варя, срочность, реплика и действие сохранены |
| `calm` / `lite` / `visible: false` | Статичная поза, циклы остановлены, смысл сохранён |
| `keyboardOpen` в чате | Варя на насесте едет вместе с полем, статично; пузырь скрыт; текст ввода и последнее сообщение видны |
| `chat-empty` → первое сообщение | Перелёт со сцены на насест ≤ 280 ms; при `calm` — мгновенно |
| `perch` на 320 px | Варя не перекрывает «Отправить», «Прикрепить» и текст ввода |

Тесты `resolveMascot` (чистая функция) проверяют приоритет §2, дедупликацию реакции, отбрасывание
чужого `spaceId`, календарь §7 и обязательные поля шаблонов реплик §6. Скриншот фикстуры не
является доказательством работающего входа в вуз, живых данных или измеренной производительности.
