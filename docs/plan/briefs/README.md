# Брифы исполнителей: общие правила

Уточнение 2026-10-29: брифы сохраняют границы владения первоначальных потоков, а не
утверждают отсутствие уже реализованного кода. Текущие проверки и ключи —
[testing.md](../../development/testing.md) и [public-search.md](../../development/public-search.md).
По просьбе владельца полный набор текущей интеграции запускается в GitHub CI;
локально выполняются только ограниченные затронутые сценарии.

Каждый поток W1–W5 читает **свой** бриф и этот файл. Обязательное чтение перед первой правкой:
[AGENTS.md](../../../AGENTS.md), [QUESTIONS.md](../../../QUESTIONS.md) (решения владельца),
[LLD](../../architecture/lld.md), [контракты](../../../contracts/), [план](../workstreams.md),
[тесты](../../development/testing.md). Код фундамента (этап 0) уже в `main` — читай его, а не
придумывай заново: протоколы в `backend/src/botai/core/`, заглушки роутеров с финальными
сигнатурами, все таблицы в `db/models.py`, фабрики в `<модуль>/factory.py`, сборка сервисов в
`botai/wiring.py`.

## Процесс

1. В своём worktree: `git fetch origin && git checkout -b feat/w<N>-<тема> origin/main`.
2. Работай вертикальными срезами: срез = код + тесты + зелёные обязательные проверки CI.
3. Коммиты: заголовок на английском в повелительном наклонении, тело на русском. Без строк соавторства.
4. PR: `gh pr create --base main` с описанием **на русском**: что сделано (FR/NFR), как проверено,
   что **не** проверено. Затем `gh pr merge --auto --squash --delete-branch`.
5. Жди CI (`gh pr checks <n> --watch`). Красный — чини в той же ветке. Не отключай проверки и не
   помечай тесты `skip`, чтобы пройти.
6. Перед следующим срезом: `git fetch origin && git rebase origin/main`. Конфликты в
   сгенерированных файлах (`backend/openapi.json`, `apps/web/src/api/*.gen.ts`,
   `backend/src/botai/contracts/schemas/`) не мержи руками — запусти `make gen`. У Alembic должна
   быть **одна голова** (`uv run alembic heads`); при двух — перенаправь `down_revision` своей
   миграции на актуальную голову.
7. Свой worktree **не удаляй** — его уберёт координатор после мержа.

## Границы

- Пиши только в своих каталогах (раздел «Владеешь» брифа). Нужна правка чужого — не делай её;
  опиши в PR в разделе «Нужно от других» и обойди через протокол или тестовую реализацию.
- `contracts/` и `backend/src/botai/core/` меняет только координатор. Если без изменения не
  обойтись — остановись и опиши это в итоговом отчёте.
- Нельзя: обходить капчу или защиту от ботов; класть пароль, cookie, токен или код в лог, событие
  задания или промпт; ходить в настоящие вузы; писать код под конкретный вуз; исполнять код,
  присланный моделью.

## Итоговый отчёт координатору

Последним сообщением: смёрженные PR (ссылки), что реализовано, что не проверено и почему, открытые
вопросы, что нужно от других потоков. Коротко, без пересказа кода.
