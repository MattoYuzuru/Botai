# Агент-хаб v3: единый агент, вузы как единицы, вложения и новый UX

Статус: **реализовано и выложено на production** (интеграция `claude/agent-hub-v3`, PR #71, 2026-10-30; доработки #72–#87 до 2026-10-31 — [раздел 7](#7-что-вошло-после-71)); приёмка выпуска — [проверки](../development/testing.md). Основание — запрос владельца от 30.10.2026
(живые проходы ВШЭ и ЦУ, разбор логов production). Решение — [ADR-0013](../adr/0013-unified-agent-hub.md).
Этот документ — бриф для всех исполнителей потоков WS1–WS6; он же фиксирует находки.
После выпуска итог переносится в [архитектуру](../architecture/overview.md),
[требования](../product/requirements.md) и [проверки](../development/testing.md).

Неизменные правила — [AGENTS.md](../../AGENTS.md): капча/MFA не обходятся, пароль только
шифртекстом в Vault, секреты не покидают Vault, текст источника — данные, write во вуз
только по одноразовому подтверждению, сеть только через EgressProxy, тесты не ходят в
настоящие вузы, в коде нет ничего под конкретный вуз, агент не пишет исполняемый parser code.
Всё остальное в харнессе агента разрешено расширять: агент Ботай должен быть свободен и
решать любую учебную задачу студента. Пользователей нет — совместимость со старыми данными
не требуется, мёртвый код удаляется.

Следующая работа над источниками — [много источников у одного вуза](many-sources.md): решение владельца
от 31.10.2026 «у вуза сколько угодно источников любого вида» (FR-055) код пока не выполняет.

## 3. Целевая архитектура

### 3.1 Тред — единственная сущность разговора

- Колонки `chat_threads.purpose` и `connect_context` удаляются. Добавляются
  `last_message_at`, `last_read_at`. Ход агента — задание `CHAT` (handler — единый агент).
- Долгие работы — **задачи** (`CONNECT`, `REPAIR`, `SYNC` с входом, `INGEST`), у каждой
  `jobs.thread_id` = тред, где их попросили. Их блоки проецируются в этот тред (как сейчас
  для connect). Тред может одновременно иметь фоновую задачу и обычный ход агента.
- Маршрутизация сообщения: если задача треда ждёт **несекретный ответ в диалоге** — сообщение
  идёт в её inbox (как сейчас); иначе запускается `CHAT`. Ответ `409` «уже идёт задание»
  при фоновой задаче больше не возникает.
- Ссылки: `botai://threads/{id}` → `/chat?thread=id`; `botai://connections/{id}`,
  `botai://documents/{id}`, `botai://attachments/{id}`. Голые ULID в тексте запрещены.
- Агент сам даёт треду короткое название (инструмент `rename_thread`), по умолчанию — из вопроса.

### 3.2 API тредов (WS1)

Исходный дизайн; окончательный контракт и все коды ошибок — [conversation.md](../../contracts/conversation.md)
(например, `POST …/read` принимает необязательный `upTo`, а не просто ставит `now`).

```ts
type ThreadOut = {
  id: string; spaceId: string | null; title: string;
  createdAt: string; lastMessageAt: string;
  unread: boolean;                       // есть сообщение агента новее last_read_at
  attention: "waiting_user" | "running" | "failed" | null; // по активной задаче/ходу
  activeTask: { jobId: string; kind: "connect"|"repair"|"sync"|"ingest"; connectionId: string | null;
                state: string; title: string } | null;
  preview: string | null;                // начало последнего текстового сообщения, ≤120
};
// GET  /api/v1/chat/threads                 → ThreadOut[] (все, по lastMessageAt desc)
// POST /api/v1/chat/threads {spaceId?, title?, clientRequestId?} → 201 ThreadOut
// PATCH /api/v1/chat/threads/{id} {title}   → ThreadOut
// DELETE /api/v1/chat/threads/{id}          → 204 (останавливает задачи треда)
// POST /api/v1/chat/threads/{id}/read       → 204 (last_read_at = now)
// POST /api/v1/chat/threads/{id}/messages {text: 0..8000, attachmentIds?: string[≤10],
//      clientMessageId?, targetJobId?} → 202 {message: MessageOut, jobId}
//      (text может быть пустым только при вложениях)
// GET  /api/v1/chat/threads/{id}/runtime → {activeJob, tasks: JobOut[], pending, receipts}
```

`MessageOut.blocks` у сообщения пользователя содержит `attachment`-блоки. Существующие
`/jobs/{id}/events` (SSE) и `/jobs/{id}/answers` сохраняются.

### 3.3 Блоки интерфейса агента (WS1 владеет `contracts/agent-ui.schema.json`)

- `text` + необязательный `quickReplies: string[]` (≤4, ≤60 символов) — кнопки быстрых
  ответов под последним ответом; нажатие отправляет текст как сообщение пользователя.
- `plan` `{id, title, steps: [{id, title, state: "pending"|"active"|"done"|"skipped"}]}` —
  план ответа; обновляется тем же `id` (upsert в истории).
- `attachment` `{id, attachmentId, name, mime, size, kind: "image"|"document"|"audio"|"other"}`.
- `task` `{id, jobId, kind, title, state, threadId, connectionId?}` — карточка задачи; если
  задача живёт в другом треде, карточка ведёт туда.
- `text.quote` `{text ≤200, blockId?}` у сообщения студента — цитата вопроса, на который оно отвечает (кнопка быстрого ответа, ответ на вопрос задачи); `confirm.details` (markdown, ≤2000) — то, что подтверждается, в одном сообщении с вопросом и кнопками. Подробно — [контракт треда](../../contracts/conversation.md) («Цитата вопроса», «Итог подключения»); добавлено после живого прохода владельца 2026-10-30.
- Markdown в `text.markdown`: GFM-таблицы, `**жирный**`, `*курсив*`, ссылки, списки, код и
  fenced-блок ` ```chart ` с JSON `{type:"bar"|"line", title?, labels: string[], series: [{name, values: number[]}]}`.

### 3.4 Инструменты единого агента (WS1)

Сохраняются: `get_schedule`, `get_deadlines`, `get_courses`, `get_grades`, `get_people`,
`get_news`, `search_documents`, `search_facts`, `search_public_web`, `request_repair`,
`request_login`. Новые:

| Инструмент | Что делает |
|---|---|
| `list_universities()` | Вузы пользователя и их источники: id, название, вид, origin, статус, последняя синхронизация, ошибка, активная задача и ссылка на её тред |
| `find_university(query)` | Справочник + выученные вузы: кандидаты с названием, сокращением, алиасами |
| `connect_source(title, connection_id?, university_id \| university_query, url?, kind_hint?, kinds?, replace_kinds?, note?)` | Подключить источник в текущем треде. Сам находит/создаёт пространство вуза. Если источник на этом origin уже подключён — возвращает `exists` со статусом и ссылками, ничего не запускает; незавершённый продолжает с текущей просьбой, работающий дополняет недостающими видами ([agent-harness](../architecture/agent-harness.md)). Если задача уже идёт в другом треде — ссылку на него. **Текущее ограничение, подлежит переработке:** «тот же источник» определяется по origin, второй источник на том же сайте не создаётся ([many-sources.md](many-sources.md)) |
| `connect_calendar(university_id?, university_query?, title?, replace_link?)` | Подключить календарь вуза по личной ссылке экспорта iCal (Яндекс, Google, Outlook): задача в текущем треде показывает, где взять ссылку, и открывает защищённое поле; ссылка не проходит через модель. Ссылка, вставленная в чат, ничего не запускает: тред спрашивает кнопками, а агент вызывает инструмент после ответа «да». **Текущее ограничение, подлежит переработке:** календарь вуза один, повтор — `exists`/«уже идёт», вторая ссылка — `replace_link`; решение владельца 31.10.2026 — календарей может быть сколько угодно ([many-sources.md](many-sources.md)) |
| `add_document_url(url, university_id?, title?)` | Публичный документ/таблица/страница (Google Sheets/Docs, PDF, HTML) как источник |
| `task_status()` | Активные и последние задачи треда и пользователя: что делается, на каком этапе, чего ждёт |
| `sync_source(connection_id)` | Обновить данные источника сейчас |
| `read_document(document_id, offset?, max_chars?)` | Читать текст документа/вложения кусками |
| `browse_source(connection_id, url)` | Живое чтение страницы/JSON подключённого источника сессией студента: только GET, только origin/allowlist подключения, через EgressProxy, результат — `<source_data>`. Оболочку SPA (текст рисуют скрипты) читает тем же правилам серверный Chromium на чтение: текст страницы и JSON, который она загрузила ([агент](../architecture/agent-harness.md), [security 0.3](../architecture/security.md)) |
| `site_map(connection_id)` | Сохранённая карта разделов источника (навигация, маршруты SPA, FAQ, поиск) |
| `fetch_public_page(url)` | Чтение публичной HTTPS-страницы без cookies (ссылка из поиска или от пользователя), через EgressProxy с разовым грантом на host |
| `remember(note)` / `forget(note_id)` | Долгая память о студенте (группа, программа, предпочтения, полезные шаги) |
| `update_plan(title, steps)` | Показать/обновить план ответа (`plan`-блок) |
| `offer_choices(options)` | Быстрые ответы к финальному тексту |
| `rename_thread(title)` | Назвать тред |
| `set_primary_source`, `ask_primary_source`, `disable_source`, `compare_sources` | Добавлены в #87 (FR-054): основной источник расписания, отключение источника кнопками приложения, сравнение двух источников ([agent-harness](../architecture/agent-harness.md)) |

Бюджет профиля `agent`: до 30 шагов, до 1,2 млн токенов за ход, 96k входа на вызов,
8k вывода, 24k символов на результат инструмента, 16 вызовов на шаг. Квоты на пользователя
поднимаются (не экономим), защита от цикла остаётся. Промпт: роль «учебный агент Ботай»,
автономность, уточнять при сомнении, подтверждать вуз, не дублировать источники, план для
сложных задач, таблицы/графики, ссылки только на UI-адреса, честность, отказ вне учёбы.

Контекст хода включает: профиль студента (вузы, источники, статусы), память, активные задачи
треда, вложения текущего сообщения (текст ≤30k символов целиком, больше — начало и указание
читать `read_document`), сводку старых ходов.

### 3.5 Вузы и источники (WS4)

- `Space` = один вуз пользователя: уникальность `(user_id, university_id)`; название из
  университета («НИУ ВШЭ»), не hostname. Без вуза — пространство «Мои материалы»
  (`university_id NULL`, одно на пользователя) для документов вне вуза.
- `Connection` = источник вуза: `title` человеческий («Единый личный кабинет», «Smart LMS»,
  «Список группы»), `kind` ∈ `portal|lms|schedule|site|sheet|doc|document|calendar|other`,
  `origin`, `entry_url` (UI-страница входа в данные, без секретных query).
- Интерфейс для WS1 (`botai.spaces`):
  - `universities.search(session, query) -> list[UniversityCandidate(id, title, short_title, aliases, score)]`;
  - `service.ensure_space(session, user_id, university_id | None) -> Space`;
  - `service.list_sources(session, user_id) -> list[UniversitySources]`;
  - `service.find_source(session, user_id, origin) -> Connection | None` (источник пользователя на сайте, самый старый,
    по всем пространствам; текущее ограничение, подлежит переработке: [many-sources.md](many-sources.md)).
- `SpaceOut` получает `shortTitle`, `aliases`; `ConnectionOut` — `entryUrl`, `threadId`,
  `activeTask`. `GET /api/v1/spaces` и `/connections` возвращают это для экрана «Учёба»
  и панели «Источники».

### 3.6 Вложения и документы (WS4)

```ts
type AttachmentOut = { id: string; name: string; mime: string; size: number;
  kind: "image" | "document" | "audio" | "other"; createdAt: string;
  documentId: string | null; ingest: "none" | "queued" | "indexed" | "failed" };
// POST   /api/v1/attachments (multipart file ≤20 MiB, threadId?) → 201 AttachmentOut
// GET    /api/v1/attachments/{id}          → AttachmentOut
// GET    /api/v1/attachments/{id}/content  → байты, Content-Type, inline, private no-store
// DELETE /api/v1/attachments/{id}          → 204 (только не отправленное)
```

- Хранение — Postgres `attachments` (bytea), владелец обязателен; новый инфраструктурный узел
  не вводится. Типы: изображения, PDF, DOCX, XLSX, CSV/TSV, TXT/MD, HTML, аудио (webm/ogg/m4a/mp3).
- При отправке сообщения с документом API создаёт `Document` в пространстве треда (или
  «Мои материалы») и сразу ставит `INGEST` с `thread_id`. Ingest **сначала** пишет текст и
  chunks (документ ищется и читается), затем фоном задаёт вопросы о таблицах и извлекает
  записи. Изображения и аудио хранятся и показываются; распознавание изображений — будущий этап, аудиофайлы не расшифровываются (диктовка в поле ввода — отдельный путь, звук не хранится).
- `attachments.service.extract_text(session, user_id, attachment_id, max_chars) -> Extract(text, truncated, kind)` —
  для контекста агента.

### 3.7 Свобода исследования источника (WS2)

- **Probe.** Новое действие планировщика `probe(r…, overrides)`: повторить наблюдаемый
  успешный GET того же origin с изменёнными значениями query (даты, страницы, размер
  страницы). Значения — шаблоны (`{weekStart}`, `{plusDays:N}`) или литералы из наблюдения.
  Результат — новое evidence с числом записей и формой. Тело/метод/host не меняются.
- **dateWindow.** `pagination: {type: "dateWindow", param, stepDays: 1..31, windows: 1..12,
  startOffset: -4..0}`: executor рендерит query заново для каждого окна со сдвинутым
  `now` (`{weekStart}` сдвигается корректно). Пустое окно не завершает обход; повтор ответа
  на разных окнах = `no_progress`. Canary проверяет ≥2 окна. По умолчанию автор берёт
  `startOffset: -1, windows: 6`.
- **Редкие данные.** Если вид данных дал ≤2 записи в текущем окне, исследователь делает
  probe следующих окон. Если и там пусто/редко — вопрос человеку обычным текстом в диалоге
  с конкретикой (диапазон дат, что найдено), ответ классифицируется в intent.
- **Поля.** Словарь `scheduleEvents` расширяется: `kindText`, `address`, `group`,
  `lessonNumber`, `links` (url+label), `attributes` (до 8 пар `{label, path}`; label — общий
  текст, без личных значений). Domain/DB: `schedule_events.kind_text, address, group_text,
  lesson_number, links JSONB, attributes JSONB`; у всех доменных строк провенанс `open_url`.
- **UI-адрес.** Compiler берёт из evidence страницу-инициатор запроса (документ, в котором
  выполнился XHR) и формирует `endpoint.uiUrl` с теми же шаблонами, что у запроса;
  lint запрещает личные значения. Normalizer пишет `open_url` записи; API отдаёт `openUrl`.
- **Карта сайта.** Наблюдение сохраняет несекретную карту origin: пункты навигации
  (label, path), маршруты SPA, обнаруженные FAQ/поисковые endpoints — таблица
  `source_sitemaps(origin, map JSONB, updated_at)`, общая как рецепт.
- **Поиск входа.** Если пользователь назвал вуз без адреса — справочник + `search_public_web`,
  предложение кандидатов человеку; глубокая ссылка («/schedule») предпочтительнее корня.
- Repair проверяет полноту горизонта (окна), а не только форму.

### 3.8 Вход (WS3)

- Разрешение auth-документа после **каждой** отправки пользователем шага (почта, пароль,
  код) армирует окно ≈15 с: POST-навигации и XHR/fetch POST из этого фрейма разрешены на
  хосты, уже одобренные для входа этого подключения (не на любой host). Совпадение с
  `form.action` больше не требуется; одноразовость — на шаг пользователя, а не на документ.
- Многошаговые формы (почта → «Далее» → пароль → код) проходят нативными полями Ботай;
  каждый шаг — новый вопрос в чате.
- Отказ guard — код `login_guard_refused` (внутренний), а не `source_unavailable`;
  агент предлагает запасной экран и повторяет шаг. Истёкшая сессия при sync → задача
  входа в треде источника + уведомление; агент сам предлагает «Войти снова».
- fakeuni: Keycloak-подобная форма с JS-отправкой на `/login-actions/authenticate?session_code=…`,
  предварительным XHR-POST проверки логина и вторым шагом пароля; SMS-шаг.

### 3.9 Интерфейс (WS5, WS6)

- **Ноутбук (≥1024px).** Чат на всю высоту справа от рейла. Верхняя полоса во всю ширину
  области: слева название треда (и подпись «Чат»), справа фиксированные кнопки
  «Источники», «Чаты», «Новый чат» — на одной линии с логотипом рейла. Лента прокручивается
  всей областью (скроллбар у правого края окна), колонка ≈48rem по центру, composer
  прижат к низу с отступом 16–24px.
- **Телефон/PWA.** Компактная шапка с иконками, composer над tab bar с safe-area,
  листы (sheets) для источников и чатов, клавиатура скрывает tab bar.
- **Скроллбар.** Один тонкий кастомный скроллбар из токенов (`--scrollbar-*`): нативный
  стиль для страницы (webkit + firefox) и `ScrollArea` для вложенных областей, проявляется
  при наведении/прокрутке. Design-lint требует использовать только его.
- **Composer.** Textarea, «+» (файл, фото/камера), микрофон, отправка; drag-and-drop на всю
  область чата, вставка изображений; чипы вложений с удалением; диктовка: запись голоса (MediaRecorder) → текст в поле через `POST /api/v1/speech/transcribe` ([speech-to-text.md](../development/speech-to-text.md); запись голосового вложения без расшифровки заменена).
- **Список чатов.** Точка непрочитанного, «ждёт вас», «работает»; отметка прочтения при
  открытии треда. Глобальный тост «Ботай просит войти в ЦУ → Открыть» при переходе треда в
  `waiting_user` вне текущего экрана. Плашки источников на экранах данных ведут в тред задачи.
- **Ответ агента.** Таблицы, графики, план, быстрые ответы, цитаты сгруппированы по
  источнику и подписаны названием источника; вьюер изображений/PDF/аудио.
- **Статусы вузов (WS6).** Один `SourceStatusBar` в шапке «Сегодня», «Расписание», «Задания»;
  плавное раскрытие (ширина через grid/transform, соседи сдвигаются анимацией, при уходе
  курсора — плавный возврат), reduced-motion без анимации.
- **Карточка события (WS6).** Расширяемый пресет `eventDetails`: время (часы), адрес
  (геометка), аудитория (дверь), кампус/здание (учебное здание), преподаватель, группа,
  онлайн-ссылки, тип занятия бейджем, `attributes` — общий вид; «Открыть в кабинете» — `openUrl`.
- **Учёба (WS6).** Вуз → список источников (название, вид, статус, обновление), «Добавить
  источник» открывает новый тред с готовым запросом; документы и вложения вуза.
- **Переходы в чат.** `/chat?thread=<id>` открывает тред; `/chat?draft=<text>` открывает новый
  тред с заполненным composer (не отправляет сам); `/chat?thread=<id>&draft=<text>` — то же
  в существующем треде. Других способов «перенаправить в подключение» нет (WS5 реализует,
  WS6 и плашки источников используют).

### 3.10 Сброс аккаунта (WS4)

`python -m botai.ops.reset_account --email E [--shared] --yes`: в одной транзакции удаляет
треды, сообщения, задания (+events/answers/checkpoints), подключения и доменные данные,
пространства, документы/chunks, факты, вложения, память агента, секреты Vault пользователя;
пишет `audit_log.kind=product_data_reset`. `--shared` дополнительно удаляет рецепты, пресеты,
карты сайтов и origins университетов, которыми не пользуется больше никто. `users`,
`auth_sessions`, `invites` сохраняются. Без `--yes` печатает только счётчики.
