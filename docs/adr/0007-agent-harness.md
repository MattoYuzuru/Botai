# ADR-0007: собственный тонкий харнес агента над DeepSeek

- Статус: **accepted**, 2026-10-27 (запрос владельца)
- Связь: [agent-harness.md](../architecture/agent-harness.md), [benchmark.md](../plan/benchmark.md)

## Контекст

Обучение вуза, починка и чат — это циклы «модель ↔ инструменты» с памятью переписки. Нужны:
кэшируемый префикс (DeepSeek даёт ≈ ×50 скидку на попадания в кэш), управление режимом
рассуждения по назначению, бюджеты, диагностика и честный учёт расхода общего ключа.

## Решение

Пишем свой небольшой харнес (`botai.agent.harness`) поверх `LlmProvider`, а не берём
агентный фреймворк. Профили «модель + `thinking` + `reasoning_effort` + бюджет» задаются
конфигурацией по назначению; значения по умолчанию выбирает [бенчмарк](../plan/benchmark.md).
Процедуры для модели — Markdown-скиллы в `agent/prompts/`, стабильный префикс.

## Почему не фреймворк

Нам нужны три вещи, которые фреймворки делают неявно и которые здесь критичны: точный порядок
префикса ради кэша, обязательная передача `reasoning_content` при инструментах (иначе 400) и
строгая граница «текст вуза — данные». Харнес на несколько сотен строк проще проверить тестами,
чем чужую абстракцию.

## Последствия

Смена провайдера — новая реализация `LlmProvider` и профили; харнес не меняется. Диагностика
остаётся в логах и `llm_usage`; студент видит только шкалу контекста.
