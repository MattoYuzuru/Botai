# ADR-0013: единый агент в треде, вуз как единица и свободное исследование

- Статус: **accepted**, 2026-10-30.
- Связь: FR-035–FR-053; [план](../plan/agent-hub-v3.md); заменяет разделение chat/connect из
  [ADR-0008](0008-conversational-connections.md) и [контракта беседы](../../contracts/conversation.md);
  дополняет [ADR-0012](0012-verified-source-factory-v2.md).

## Причина

Живые проходы 29.10.2026 показали: агент чата не умеет подключать источник и отправляет
пользователя в другой тред, которого нет в списке; исследователь выучил расписание на одну
неделю и не проверил соседние; guard входа заблокировал JS-отправку формы и сообщил «сайт не
отвечает»; пространства названы по hostname. Причина общая — две разные сущности (чат и
подключение) и закрытый, слишком узкий харнесс исследования.

## Решение

1. **Один агент на тред.** Тред не имеет назначения. Ход агента (`CHAT`) имеет полный набор
   инструментов: данные, источники, подключение, вход, документы, живое чтение
   подключённого источника и публичных страниц, память, план. Долгие задачи
   (`CONNECT/REPAIR/SYNC/INGEST`) привязаны к треду, где их попросили, и видны в нём.
2. **Вуз — пространство, источники — подключения.** Пространство уникально на
   `(пользователь, вуз)` и названо по вузу; источник имеет человеческое название и UI-адрес.
3. **Свобода исследования в декларативных рамках.** Планировщик может повторять наблюдаемые
   GET с изменёнными датами/страницами (`probe`), рецепт умеет окна дат (`dateWindow`),
   редкие данные проверяются на соседних окнах и уточняются у человека. Поля события
   расширяются, UI-адрес компилируется из evidence. Parser code по-прежнему не допускается.
4. **Вход по шагу пользователя.** Разрешение POST привязано к отправке шага человеком и
   одобренным хостам входа, а не к точному `form.action`.
5. **Не экономим на агенте.** Бюджеты хода увеличены; защита от цикла и квоты остаются.

## Последствия

- Миграции удаляют `purpose/connect_context`; совместимость со старыми клиентами не нужна
  (пользователей нет). Флаги research/factory v2 удаляются вместе с выключенными путями.
- Живое чтение источника чатом (`browse_source`) расширяет поверхность: только GET, только
  allowlist подключения, через EgressProxy, результат — данные `<source_data>`, без секретов.
  Страница, которую рисует JavaScript, читается серверным Chromium на чтение теми же примитивами,
  что rendered-рецепты ([security 0.3](../architecture/security.md)).
- `fetch_public_page` — разовый грант EgressProxy на host публичной HTTPS-страницы, без cookies,
  приватные диапазоны закрыты.
