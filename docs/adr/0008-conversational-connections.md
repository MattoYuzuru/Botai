# ADR-0008: подключение источника в обычной беседе

- Статус: accepted, 2026-10-28; запрос владельца.
- Требования: FR-003/004/007/008/016/022/030/031, NFR-001/003/004/010/012/013.

## Контекст

Раздельный экран подключения с фиксированными URL-полями мешает уточнить, что уже присланная страница и есть расписание или что дедлайнов в источнике нет. Перестановка вопроса после ответа нарушает хронологию. Короткий SSE buffer не заменяет историю беседы.

## Решение

Переиспользовать ChatScreen и существующий CONNECT worker. Thread purpose/context и связывание job/connection — серверные данные, не UI-эвристики. Обычный текст подключений идёт в durable inbox того же worker; пароль/MFA — напрямую в Vault через прежний защищённый API. Публичные блоки сохраняются отдельными стабильными turns, tickets и значения секретов — никогда. Контракт — [conversation.md](../../contracts/conversation.md).

Отдельный чат-агент, параллельно управляющий тем же входом, не вводится: он создал бы две независимые очереди и конкуренцию за браузер. Отдельная форма мастера не является основным путём. Структурированные controls остаются для секрета, выбора и конкретного подтверждения.

## Последствия

Нужны additive миграция метаданных/идемпотентности, server recovery и проекция событий; старые URL подключений получают совместимый переход в чат. При отсутствии спецификации повтор настройки — CONNECT, не REPAIR. На несколько origin приходятся отдельные источники одного пространства в одной беседе. Старые снимки и рецепты не подменяются.
