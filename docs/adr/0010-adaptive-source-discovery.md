# ADR-0010: адаптивное исследование источника перед составлением рецепта

- Статус: **accepted**, 2026-10-28, по запросу владельца.
- Требования: FR-005–FR-009, FR-016, FR-032, NFR-004–NFR-008, NFR-013.
- Связанные решения: [ADR-0005](0005-source-adapter-factory.md),
  [ADR-0009](0009-rendered-html-recipes.md).

## Контекст

Обход первых шести ссылок в порядке меню не соответствует задаче «подключи вуз, вот
мои курсы». Расписание может находиться в конце меню, а курсы и задания — в другом
разделе. Модель получала готовую выборку и не могла выбирать следующий переход.
Кроме того, положительный ответ API с токеном не доказывает, что новый браузер сохранил
состояние авторизации интерфейса.

## Решение

Перед автором рецепта работает ограниченный цикл исследования. Модель получает
очищенные DOM и наблюдаемые ответы сети, выбирает переход или раскрытие данных по
идентификатору, а исполнитель проверяет выбор и выполняет действие. Модель не создаёт
произвольные URL, селекторы, JavaScript или HTTP-запросы. Смена состояния страницы
делает прежние ссылки на элементы недействительными.

При общей просьбе подключить источник включается обнаружение поддерживаемых видов
данных. Явно перечисленные пользователем виды остаются границей поиска. Отсутствующие
или исключённые виды не добавляются обратно моделью. Само название раздела ещё не
является доказательством данных: итоговые источники проходят schema/lint и canary.

Навигация разрешена внутри источника через EgressProxy и режим чтения. Для вкладок
используется отдельная проверяемая возможность `role=tab` с существующей панелью,
без форм и опасных действий; обычный произвольный click остаётся запрещён. Капча,
MFA, новые хосты и операции записи сохраняют существующие человеческие подтверждения.
Общий Web Search этим решением не добавляется.

Бюджеты одного исследования: до 10 шагов, 12 представлений, 200 наблюдаемых запросов,
90 секунд и 150 000 токенов; действует также общий бюджет задания. Повторяющиеся
действия без новых данных останавливаются. Исчерпание бюджета обозначается как
ограничение исследования, а не как доказанное отсутствие данных в вузе.

Состояние входа включает ограниченные localStorage/sessionStorage только разрешённых
HTTPS-origin. Оно шифруется вместе с сессией в Vault и восстанавливается до первого
скрипта страницы. В модель и диагностические журналы значения не передаются. Если
отрисованная страница всё ещё просит вход, допускается одна попытка повторной
авторизации через LoginFlow; затем возвращается явная ошибка входа.

## Совместимость и последствия

Публичные схемы рецептов и API не меняются, миграция БД не нужна. Старые сессии читаются
с пустым дополнительным состоянием; прежние задания с явно заданными видами сохраняют
свою область. Провайдер планировщика объявляет отдельную возможность, чтобы старые
фикстуры автора не расходовались на новые запросы исследования.

После подтверждения синхронизации продолжаются по декларативному рецепту без модели.
Исследование станет дороже фиксированного обхода, но управляется бюджетами и наблюдаемой
трассой. Оно обнаруживает только реально увиденные страницы и ответы; полнота всех
внутренних эндпоинтов источника не заявляется.

Проверка выполняется в CI на синтетическом вузе: дальняя ссылка в меню, курсы и разные
виды данных, безопасная JS-вкладка, устаревшие ссылки, восстановление origin storage,
повторный вход, инъекции, пределы исследования и обычный canary/sync. Настоящий вход
проверяет владелец своими учётными данными.

## Уточнения реализации 2026-10-29

Исходное решение выше относится к срезу 28 октября. Следующее изменение добавило
внутреннюю nullable-колонку `connections.data_scope` (миграция `9c2a7184be6d`), чтобы
выбор студента сохранялся при последующих sync и не сужал общий рецепт. Поэтому
утверждение «миграция БД не нужна» не распространяется на этот следующий срез.
Публичная схема рецепта осталась прежней.

Публичный Web Search добавлен отдельным сервисом Exa/DeepSeek и не заменяет цикл
авторизованного наблюдения. Текущее поведение, readiness SPA, причины неполного
исследования и область чтения — [adaptive-observation.md](../research/adaptive-observation.md).
Ключи и fallback поиска — [public-search.md](../development/public-search.md).
