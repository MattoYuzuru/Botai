# ADR-0004: своя схема блоков интерфейса агента вместо полного A2UI

- Статус: **accepted**
- Дата: 2026-10-26
- Связь: FR-006, FR-007, [contracts.md](../architecture/contracts.md) §4

## Контекст

Агент должен задавать уточняющие вопросы настоящими элементами интерфейса
(чекбоксы, радио, поля, подтверждение), а не просить ответить текстом. Google
A2UI (Apache-2.0) решает ровно эту задачу: агент отдаёт декларативный JSON, а
клиент рисует его своими компонентами.

## Решение

Берём **идею и дисциплину** A2UI, но описываем собственное узкое подмножество
`AgentUiBlock` (text, thinking, choice, input, confirm, summary, approval,
login). Клиент рендерит только известные типы и никогда не исполняет ничего из
блока.

## Почему не A2UI целиком

Полная спецификация шире нашей задачи и ещё движется к 1.0; узкая схема
проверяется JSON Schema в CI, рисуется компонентами нашей дизайн-системы и
не даёт модели возможности описать произвольный интерфейс. Переход на A2UI
остаётся возможным: наши типы — его подмножество по смыслу.

## Последствия

Любой новый тип блока — изменение контракта с ревью и обновлением фронтенда.
Неизвестный тип блока клиент показывает как текст с пометкой, а не игнорирует.
