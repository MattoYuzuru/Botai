# ADR-0002: декларативный рецепт как единственный мост обучение → исполнение

- Статус: **accepted** (архитектурное основание продукта)
- Дата: 2026-10-26
- Связь: FR-008–FR-011, NFR-008, [overview.md](../architecture/overview.md)

## Контекст

Агент, который каждый раз заново «понимает» сайт вуза, непредсказуем и дорог:
LLM в горячем пути означает стоимость и недетерминизм на каждую синхронизацию
каждого пользователя.

## Решение

Всё, что агент понял про вуз, выражается как **рецепт** — декларативный JSON
(origin, GET-эндпоинты, пагинация, JSON Pointer на поля, трансформации), общий
для всех студентов вуза и не содержащий личных значений. Исполнение рецепта —
обычный HTTP плюс разбор, без модели.

Если поведение нельзя выразить рецептом — задание обучения не завершено, а не
«дополняется моделью на лету».

## Последствия

- Стоимость: обучение дорогое и редкое, синхронизация бесплатная.
- Рецепт версионируется, проходит lint (нет личных значений) и canary на
  сессии автора; неудачная ревизия откатывается.
- Поломка сайта вуза даёт `recipe_drift` — явное состояние с задачей на
  переобучение, а не тихую деградацию.
- Ограничение: сценарии, требующие рассуждения над содержимым страницы,
  обслуживаются отдельным путём (RAG, agent retrieval) и помечаются как менее
  надёжные.
