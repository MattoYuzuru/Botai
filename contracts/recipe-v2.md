# Рецепт v2: контракт фабрики

Статус: реализовано, выпуск проверяется отдельно. FR-008–FR-011, FR-018, FR-039–FR-042,
NFR-004–NFR-008, NFR-012–NFR-013. Авторитетная схема — `recipe.schema.json`.

## Совместимость и потребители

`version=1` сохраняет исходную строгую схему. Новые узлы разрешены только при `version=2`.
Затронуты W0 schemas/spec models, W2 Gateway/session, W3 author/lint/canary/recipe executor,
диагностика и synthetic fixtures. Старый binary не может читать v2; новый reader читает обе версии. Автор всегда получает
схему v2 (флаг производства удалён). Рецепты не обновляются автоматически и не переписываются
backfill. Окна дат, `uiUrl`, `links` и `attributes` ниже существуют только в v2; v1 их не знает и
отклоняет схемой и typed-моделью. Доменные сущности расширены в `domain.schema.json`
(`openUrl`, поля карточки занятия).

## Авторизация

`auth.type=session`, `version=1`, `bindings` содержит до четырёх сочетаний `cookies:boolean`
и `bearer:none|observedAuthorization`. Request/GET-bootstrap ссылается через `authBinding`.
Audience всегда exact `recipe.origin`, а не allowlist: credentials не отправляются на другой
origin даже при разрешённом redirect. Значений токена, storage key, произвольного header или
refresh URL в спецификации нет. Автор выбирает только ephemeral ID наблюдаемого запроса;
executor проверяет происхождение/метод/путь/параметры, компилирует binding и удаляет evidence ID.
Отказ конкретного endpoint не доказывает утрату браузерного входа. Refresh использует LoginFlow.

## Вложенные коллекции, время и повторения

Ответ выбирает прежний `itemsPath`/`itemsSelector` либо `collections` глубиной 1–4, с уникальными
alias `as` (кроме `item/root`). Каждый уровень разворачивается только внутри предыдущего.
`from` выбирает leaf `item`, `root` или ancestor alias. `compose.type=dateTime` соединяет
наблюдаемые дату и время в явной IANA timezone; `dayOffset` и `fold` задаются явно.
Произвольных выражений, кода и рекурсивного поиска нет. Reference проверяется до чтения.

`expand.type=weekly` разрешён только для занятий: source start/until, дни недели, start time,
end time либо duration, explicit timezone, horizon до 93 дней, до 512 событий серии. Так читается
источник, который отдаёт **правило повторения** (`startDate`, `endDate`, `dayOfWeek`, время,
интервал), а не календарь.

- `weekdays` — ISO-число 1–7 (1 — понедельник), цифра строкой либо **слово источника** из
  закрытой таблицы без учёта регистра: `monday…sunday`, `mon…sun`, `mo…su`, `понедельник…воскресенье`,
  `пн…вс` (точка в конце допустима). Список слов и чисел допустим. Другое («mon,wed», «по средам»)
  не угадывается и отклоняет endpoint (`fields`).
- `intervalWeeks` — число 1–4 **или** скаляр-ссылка на поле интервала в правиле источника
  (`{"from": "row", "path": "/…/interval"}`, значение 1–4). Число > 1 требует `anchorDate`;
  интервал из источника отсчитывается от недели `anchorDate`, а без него — от недели `startDate`
  правила. Значение вне 1–4 отклоняет endpoint.
- Исключения и дополнительные даты берутся из источника.
- ID экземпляра: `occ1:` + хеш от стабильного ID серии (`externalId` — собственный id правила, не
  название курса) и номинальных локальных даты/времени; не зависит от индекса или окна. Префикс
  `occ1:` — признак «экземпляр правила». Правило говорит только о днях своего горизонта
  (`horizon.from`..`+days`, с полуночи первого до полуночи после последнего дня в `timeZone`);
  адаптер отдаёт это окно в итоге чтения (`EndpointOutcome.expanded`). Normalizer снимает будущий
  экземпляр, только если он лежит **внутри окна этого чтения**, правило его больше не порождает и
  вид прочитан полностью и ему верят (вид в `complete_kinds` и не `suspicious`). Окно скользит
  вперёд каждый день, а repair может сократить `horizon.days`: экземпляры вне окна не трогаются и
  не помечаются. Прошедшие остаются. Если у вида несколько weekly-endpoint, берётся пересечение их
  окон; если ни один не разворачивает правила, окна нет и ничего не снимается.
  Остальные пропавшие будущие занятия, которые источник перечислял сам, получают `changed=true` и
  не удаляются.
- **Известное поведение, решение владельца ждёт** ([QUESTIONS.md](../QUESTIONS.md)): отменённое
  занятие одного дня правила (источник исключил дату через `excludeDates`) молча исчезает из
  расписания, а не остаётся с отметкой «отменено»; перечисленное источником занятие в такой
  ситуации получает `changed=true`.
- Неизвестная/неоднозначная дата и переполнение не заменяются догадкой.

Не собирать `startsAt` из `startDate` правила: получится одно занятие из прошлого, которое canary
принимает как непустое. Поля `startsAt`/`endsAt` при `expand` в `fields` не пишутся.

Лимиты: 10 000 узлов коллекций, 5000 leaf/instance записей endpoint и 20 HTTP страниц.
Пагинация считает верхнюю коллекцию, не количество развёрнутых занятий. Limit/cycle не
обозначаются полной выборкой; предыдущие отсутствующие строки не помечаются пропавшими.

## Повторяющийся ключ query

Адрес `?state=a&state=b&state=c` — один ключ, три значения; запрос «только `state=a`» читает другие
записи. В v2 значение `request.query[ключ]` — строка **или список** из 2–8 строк (литералы и
шаблоны, порядок сохраняется):

~~~json
"query": {"state": ["backlog", "inProgress", "review"], "limit": "50"}
~~~

- Только v2, только GET (схема отклоняет список у POST и у v1). `pagination.dateWindow` двигает
  ключ с **одним** шаблоном даты; список у такого ключа недопустим.
- Compiler (`learn/auth_bindings.py`) сравнивает ключи наблюдённого запроса и описания как
  **мультимножества**: ключ, отправленный пять раз, должен вернуться пять раз. Каждое значение
  описания соответствует своему наблюдённому значению того же ключа (литералы забирают своё первыми,
  шаблон — оставшееся); порядок не важен. Находка автору называет ключи и число значений
  (`state×5` / `state×1`), но не сами значения.
- Executor передаёт список в HTTP-клиент: ключ повторяется в адресе в том же порядке. Для чтения
  отрисованной страницы (`browserPlanRef`) ключ, который повторяет адрес самой страницы, также
  становится списком (до 8 значений); шаблон на таком ключе недопустим.
- `uiUrl` (адрес для человека) повторяющиеся ключи не переносит.
- Probe (`learn/probe.py`) повторяющийся ключ не подменяет: одно значение не заменит несколько.
- Lint: значения списка проверяются как шаблоны и как литералы. Значение **query**, целиком
  состоящее из слов общего словаря статусов (`sources/states.py`: `inProgress`, `IN_PROGRESS`,
  `awaiting-review`, `backlog`...), не считается личным, даже если встречается в ответах: это
  фильтр по статусу, который автор видит без маски и который compiler уже сверил с запросом
  страницы. Исключение действует только для query и только для слов словаря: имя, логин, код
  группы, любое значение с цифрами (`jSmith`, `ivanPetrov`, `deLaCruz`, `PETROV_AA`, `ГРП-26`)
  по-прежнему отклоняется (`observed.value`); в пути и в теле исключения нет.

## Путь запроса и слова «текущий студент»

Сегмент пути, который в наблюдении показан словом `me`, `my`, `mine`, `own`, `self` или `current`,
сайт сам понимает как текущего студента. Значение из другого ответа (id из bootstrap) — не то же
самое: адрес с ним отвечает «не найдено». Compiler отклоняет `{имя}` на месте такого слова
до любого запроса: целым сегментом пути или тем, что placeholder поглотил между префиксом и
суффиксом (`/students/{id}.json` против `/students/me.json`, `user-{id}` против `user-me`) —
`evidence_path_literal_replaced` с номером сегмента; значением query (`?student=me` → `{id}`) —
`evidence_query_literal_replaced` с именем ключа. Имя ключа в находке показывается, только если
lint принял бы его как имя (не секретоподобное, до 40 знаков из `[A-Za-z0-9_.-]`), иначе `<ключ>`.
Подстановка из bootstrap остаётся допустимой вместо идентификатора, который в наблюдении скрыт
меткой `<v…>`.
Находки compiler автору выводятся словами (`FactoryCompileError.feedback()`: код, что он значит,
место), а студенту — фразами `learn/words.py` без кодов.

## Browser replay

`request.browserPlan` версии 1 разрешён только у rendered GET HTML, без body. План — до
восьми структурных шагов с frame chain до трёх same-origin frames: проверенная ARIA tab,
native date, native select, наблюдаемый `rel=next` и bounded ready wait. Date использует
existing date builtin; select — наблюдаемую опцию. Date/select требуют owning region и
проверяемый GET/effect. Custom calendar или неизвестная кнопка не получают generic click.

Модель выбирает current action/plan reference, executor компилирует structural descriptors.
В новом браузере перед каждым действием повторно проверяются uniqueness, тип, семантика,
frame/origin и ожидаемый эффект. CAPTCHA/POST/WS не становятся разрешёнными от наличия плана.
Пустой ответ требует settled structure/empty evidence; timeout/cap/cycle остаётся неполным.

## Окна дат и адрес страницы

`pagination.type=dateWindow` — `{param, stepDays 1..31, windows 1..12, startOffset -4..0}`.
Окно i двигает **все** date-шаблоны query на `(startOffset + i) × stepDays` дней в часовом поясе
источника, поэтому `{weekStart}` сдвинутой даты — понедельник той недели. `param` — ключ query, чей
шаблон состоит только из date-builtin (`{today}`, `{weekStart}`, `{plusDays:N}`, `{minusDays:N}`).
Обход обязан содержать окно 0 (`startOffset + windows − 1 ≥ 0`): компилятор проверяет, что одно из
окон воспроизводит значение, которое браузер реально отправил. Только GET без `render`,
`browserPlan`, `body` и `expand`; параметры `limit`, `maxPages`, `cursorPath` и `totalPath` вместе с
окном недопустимы. Пустое окно не завершает обход; ответ, повторяющий окно целиком, —
`no_progress`; сбой окна — сбой endpoint; полный обход без записей — `empty`. При `{weekStart}` в query `stepDays` кратен 7; для видов со временем в `identity` обязательно время
записи (`startsAt` для занятий). Для расписания автор по умолчанию берёт
`startOffset: -1, windows: 6, stepDays: 7`.

`endpoint.uiUrl: {path, query}` — страница источника, где студент видит записи (шаблоны те же, что у
запроса, сдвигаются тем же окном). Выводит компилятор из страницы, чей скрипт сделал запрос;
автор его не задаёт. Литералы — только структурные слова небольшого allowlist (`schedule`, `week`,
`view`...) или слова, которые уже есть в API-запросе рецепта; логин, фамилия, код группы, любое
значение с цифрами недопустимы (lint `uiurl.personal`). Страница входа адресом не бывает. Executor кладёт результат в `Record.open_url` → `open_url` доменной
строки → `provenance.openUrl` API. У HTML-endpoint `open_url` — сама загруженная страница.

## Секции карточки занятия

Только `scheduleEvents`, только v2, рядом с `fields` в `response`:

- `links` — до 4 элементов `{url: <скаляр>, label: <скаляр> | "общий текст ≤40"}`; пустой url
  пропускается; в записи остаются только http(s)-ссылки без дублей;
- `attributes` — до 8 элементов `{label: "общий текст ≤40", path|selector, from?, …}`; подпись не
  содержит значения из данных (lint сверяет с наблюдёнными).

В `fields` добавлены скаляры `kindText`, `address`, `group`, `lessonNumber`; имена `links` и
`attributes` в `fields` запрещены.

## Выпуск и откат

Reader и producer v2 выпускаются вместе (флаги `BOTAI_RESEARCH_ENABLED` и
`BOTAI_FACTORY_V2_ENABLED` удалены, оба режима были включены в production). Откат на binary до v2
после активации требует адресного отката ревизий/парковки подключений; нельзя просто подставить
старый образ.

Основы времени: [Python zoneinfo](https://docs.python.org/3.13/library/zoneinfo.html),
[datetime.fold](https://docs.python.org/3.13/library/datetime.html#datetime.datetime.fold).
Playwright: [frames](https://playwright.dev/python/docs/frames); использование API сверяется
с закреплённой в проекте версией, а не только с обновляемым сайтом документации.
