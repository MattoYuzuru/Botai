# Потоки: SSE заданий и WebSocket входа

Контракт между API, PWA и BrowserSvc. Смысл — [архитектура §5](../docs/architecture/overview.md).

## 1. SSE: поток задания

`GET /api/v1/jobs/{jobId}/events` · `text/event-stream` · требует сессии пула и
владения заданием.

| `event:` | `data:` | Когда |
|---|---|---|
| `status` | `{state, stage, startedAt, elapsedMs}` | При смене этапа; `state` ∈ `queued/running/waiting_user/done/failed/cancelled` |
| `block` | `AgentUiBlock` ([схема](agent-ui.schema.json)) | Каждый новый блок интерфейса агента |
| `block_update` | `{id, patch}` | Обновление блока по `id` (например `thinking.state: running → ok`) |
| `error` | problem+json | Ошибка задания; поле `code` из перечня контрактов §7 |
| `done` | `{result}` | Задание завершено |

Правила:

- У каждого блока стабильный `id` (ULID). Повторная доставка того же `id`
  идемпотентна: клиент заменяет, а не дублирует.
- Переподключение — по `Last-Event-ID`. Сервер отдаёт пропущенные события из
  буфера задания; буфер живёт до завершения задания + 10 минут.
- Heartbeat — комментарий `:keepalive` каждые 15 с.
- `waiting_user` обязателен, когда есть блок с `required: true` без ответа.
  Клиент поднимает этот блок наверх экрана ([ProgressWall](../docs/design/mascot.md)).
- Поток **не передаёт** содержимое страниц вуза, секреты и промпты модели.

Ответ на блок: `POST /api/v1/chat/threads/{id}/answers` или
`POST /api/v1/jobs/{jobId}/answers` с телом `{blockId, values}`.
Повторный ответ на отвеченный блок — `409 block_answered`.

## 2. WebSocket: сессия входа

Открытие: `POST /api/v1/connections/{id}/login-session` → `{sessionId, wsUrl,
ticket, expiresAt}`. Тикет одноразовый, живёт 60 с, гасится при upgrade.

Проверки при upgrade: валидный тикет, совпадение `Origin`, владение
подключением. Зритель у сессии один: новый тикет побеждает, прежний сокет
закрывается кодом 4001 (иначе переподключение упирается в полуоткрытый сокет).

### Сервер → клиент

| `t` | Поля | Смысл |
|---|---|---|
| `frame` | `seq, mime:"image/jpeg", w, h, data, inputTs?` | Кадр экрана (CDP screencast); `inputTs` — метка последнего учтённого ввода клиента, по ней клиент меряет задержку без синхронизации часов |
| `state` | `url, title, loading` | Где сейчас браузер |
| `needs` | `what: "mfa"\|"captcha"\|"choice"\|"input", hint` | Что должен сделать человек |
| `success` | `{}` | Признак входа сработал, состояние сессии снято |
| `expired` | `{reason}` | TTL сессии истёк, контекст уничтожен |
| `error` | problem+json | Ошибка; `source_bot_protection` означает «нужен человек», автоповторов нет; `login_guard_refused` — наш guard остановил запрос входа, сайт работает |

### Клиент → сервер

| `t` | Поля |
|---|---|
| `mouse` | `kind: "move"\|"down"\|"up"\|"click", x, y, button, ts` |
| `key` | `kind: "down"\|"up"\|"char", code, text, ts` |
| `scroll` | `x, y, dx, dy` |
| `resize` | `w, h` |
| `ack` | `seq` — подтверждение кадра, для управления темпом |
| `done` | `{}` — пользователь считает вход завершённым |

### Жёсткие правила

1. Кадры и события ввода **не пишутся на диск**, не попадают в логи, метрики и
   трейсы. Это проверяется тестом.
2. TTL сессии входа — минуты; по истечении контекст браузера уничтожается
   вместе с профилем в tmpfs.
3. Один активный контекст браузера на пользователя.
4. Весь исходящий трафик контекста идёт через EgressProxy с allowlist из
   `login-preset.allowHosts`. Переход на хост вне списка — `egress_blocked`,
   и хост показывается пользователю.
5. Капча и MFA не автоматизируются никогда: сервер только показывает `needs`.
6. Перед первым входом UI обязан показать предупреждение о том, что экран и
   ввод проходят через сервер ([security.md](../docs/architecture/security.md) T8).

## 3. Лимиты

| Параметр | Значение |
|---|---|
| Размер сообщения клиента | ≤ 8 КБ |
| Частота сообщений клиента | ≤ 120/с, дальше — отбрасывание |
| Частота кадров | до 30/с, адаптивно по `ack` вниз до 10/с ([ADR-0001](../docs/adr/0001-login-form-mirroring.md)) |
| Нарушений до закрытия | 100 |
| TTL сессии входа | 10 минут, продление по активности до 30 |
| Буфер SSE задания | до 500 событий или 2 МБ |
