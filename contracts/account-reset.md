# Сброс продуктовых данных аккаунта

Статус: accepted, 2026-10-29. FR-023, NFR-001, NFR-013.

Оператор может очистить продуктовые данные одного однозначно установленного владельца,
сохранив `users`, `auth_sessions`, приглашения и права. Очистка не является публичной
операцией API. Перед ней нужны защищённая резервная копия и остановка API, worker и заданий
владельца.

## Команда

```
python -m botai.ops.reset_account --email E [--shared] [--yes]
```

Без `--yes` ничего не удаляется: печатаются числа строк по таблицам (и предупреждение, если у
аккаунта есть активные задания). С `--yes` всё выполняется **одной транзакцией**.

Удаляется всё, что создал пользователь: треды и сообщения, вложения, задания вместе с событиями,
ответами и проверочными точками исследования, подключения и все доменные данные из них,
пространства, документы и их текст, факты, память агента, подтверждения действий и секреты
Vault (`secrets`). Остаются `users`, `auth_sessions`, `invites`, `audit_log` и `llm_usage`
(учёт использования). В `audit_log` пишется `product_data_reset` — серверный маркер ниже
(в `detail` только числа удалённых строк).

Таблицы не перечислены в коде: удаляется каждая таблица схемы, у которой есть `user_id` или
внешний ключ на такую (так уходят `job_events` и `job_answers`, не имеющие `user_id`). Таблица
без владельца, не отнесённая к сохраняемым или общим, останавливает команду и тест схемы: новая
таблица потока (`user_memory`, `attachments`, …) не забывается, а осознанно классифицируется.

`--shared` дополнительно удаляет общее, чем не пользуется больше никто (чужие подключения
проверяются по `connections`): рецепты (`adapter_specs`, в том числе `doc:<id>` документов),
пресеты входа (`login_presets`), карты сайтов (`source_sitemaps`, когда таблица есть) и
записи `universities` без пространств других пользователей. Числа без `--yes` и с `--yes`
совпадают. Повторный запуск ничего не находит и ничего не меняет в чужих данных.

`GET /api/v1/me` может возвращать заголовок `X-Botai-Data-Reset` — время последнего
сброса в миллисекундах Unix. Значение получается из серверного события
`audit_log.kind=product_data_reset` только для аутентифицированного `user_id`.
Заголовок не содержит секретов; без сброса отсутствует. Ответ не кэшируется.

Клиент до отправки сохранённой очереди сверяет этот маркер с локальной отметкой
этого аккаунта. При новом маркере он удаляет только его старые сообщения очереди
(`createdAt <= resetAt`), привязки заданий и снимки BotAI, затем запоминает маркер.
Новые сообщения, созданные после сброса, сохраняются. Повторный ответ с тем же
маркером ничего не очищает. Аккаунт, cookie входа, настройки оформления, чужие
очереди и данные других origin не затрагиваются.

Совместимость: заголовок optional, JSON `MeOut` не меняется. Потребители: API auth,
операторская очистка, PWA API-клиент, очередь чата и offline snapshots. Старый клиент
может игнорировать маркер, поэтому для завершения очистки требуется перезагрузка
на актуальную версию PWA. Проверки включают изоляцию владельца, идемпотентность,
сбой хранилища и очистку во время ожидающей проверки сессии.
