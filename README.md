# BotAI

Учебный хаб студента: расписание, дедлайны, задания, оценки и документы из
нескольких вузов в одном месте, плюс **свободный агент-harness**, который
подключает вузы, читает и склеивает источники, отвечает на вопросы, пишет код,
управляет браузером и выполняет учебные действия. Веб-приложение (PWA), ставится
ярлыком на телефон, открывается из России без VPN.

**Статус на 31 октября 2026: идёт пивот v4 — переход от ограниченного MVP к
свободному harness.** Production (https://botai.mnema.app) работает на старой
архитектуре; новая описана в [docs/v4/](docs/v4/README.md) и реализуется по
[плану](docs/v4/05-implementation-plan.md). Всё, что противоречит v4, устарело.

**Пилот 2026-10-31 (реализовано):** фаза 0 — мягкие лимиты, feature-flag `agent_engine`, остановка research без прогресса; login UX — native-first, ограниченное подтверждение «Я вошёл», качество/реконнект удалённого экрана. Документы — [08](docs/v4/08-login-ux.md), [09](docs/v4/09-prod-login-incidents.md), [10](docs/v4/10-limits-and-research.md).

**Живой бенчмарк 2026-10-31:** 3/3 сценария успешно — вход в ВШЭ по кредам из
Keychain (значения не видны модели), чтение сессии Chrome, 174 задания ЦУ на
динамической странице. Детали и ограничения — [docs/v4/04-benchmark.md](docs/v4/04-benchmark.md).

## В чём идея

Обычные агрегаторы поддерживают вуз, только если кто-то написал под него парсер.
Здесь вуз подключает **агент**, у которого есть всё, что есть у внешнего harness:
браузер, сеть, код, файлы, сессии и действия. Студент говорит «добавь источник»
или просто «подключи мой вуз» — агент сам определяет, что это (сайт, LMS,
календарь, таблица, документ), входит, исследует, пишет парсер/playbook,
сохраняет его версией и дальше обновляет данные.

У вуза может быть **сколько угодно источников любого вида**; данные склеиваются
и наслаиваются с приоритетом, происхождение видно. Всё, что агент увидел и
скачал, индексируется в RAG; ответ чата всегда может сослаться на источник и
время.

Отличия v4 от прежней версии:

- один контур вместо «обучения» и «исполнения»: модель может участвовать в любой
  задаче;
- агент пишет код и запускает его в песочнице, управляет браузером полностью,
  ходит в любую сеть, видит cookie/сессии (первичные пароли скрыты);
- write-действия и формы разрешены по политике владельца, а не запрещены;
- капча/антибот — техническая задача, а не архитектурный запрет;
- лимиты стоимости и времени — мягкие и настраиваемые, без глухих стен;
- живые проверки на настоящих вузах с реальными кредами — норма, а не исключение;
- «Мои материалы» и отдельные «Документы/Вложения» удалены: вуз — пространство
  своих источников.

## Запуск

```bash
make db           # Postgres для разработки
make check        # линтеры, типы, тесты, генерация
make dev-api      # API на :8000
make dev-worker   # фоновый воркер
make dev-web      # PWA на :5173
make bench        # агентский бенчмарк L2
```

Живой бенчмарк с настоящими кредами — `bench/live/` (см.
[docs/v4/04-benchmark.md](docs/v4/04-benchmark.md)). Креды выдаются через macOS
Keychain, не печатаются и не попадают в репозиторий.

## Откуда что взято

Маскот и часть решений по входу переиспользуются из проекта владельца
`doodle_vibe`; дизайн-метод (OKLCH-токены, роли типографики, плотность,
design-lint) — из `BPMN.Space`. Внешние проекты `workflow-use` и `Integuru`
изучены как идеи; их код не заимствуется (AGPL-3.0).

Проект — pet-проект владельца и друга; публичная регистрация, биллинг и
юридическое соответствие не планируются. Лицензия — MIT.
