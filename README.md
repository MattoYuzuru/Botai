# BotAI

Учебный хаб студента: расписание, дедлайны, оценки и домашки из нескольких
вузов в одном месте, с агентом, который отвечает на вопросы по этим данным.
Веб-приложение (PWA), ставится ярлыком на телефон, открывается из России без VPN.

**Статус на 31 октября 2026: MVP реализован и выложен на production (https://botai.mnema.app).**
Работают подключение, вход, обучение рецептов, синхронизация, PWA, единый агент в чате
([агент-хаб v3](docs/plan/agent-hub-v3.md)), диктовка, календарь по ссылке iCal и склейка нескольких
источников расписания одного вуза. Живую проверку настоящих вузов ведёт владелец; её результаты, текущая
приёмка и ограничения — в [документе о проверках](docs/development/testing.md).
Успешный фикстурный тест не подтверждает подключение настоящего вуза.
Решения владельца — [QUESTIONS.md](QUESTIONS.md),
архитектура в картинках — [HLD](docs/architecture/hld.md) и [LLD](docs/architecture/lld.md).

## В чём идея

Существующие агрегаторы поддерживают вуз, только если кто-то вручную написал
под него парсер. Здесь вуз подключает **агент**:

1. Студент пишет в любом чате название вуза, ссылку на нужный раздел и пояснения — один агент
   ([ADR-0013](docs/adr/0013-unified-agent-hub.md)) уточняет вуз и подключает источник прямо в этом треде.
   Исходные path/query сохраняются; общая просьба включает обнаружение поддерживаемых
   видов данных, явные ограничения пользователя сохраняются. Публичный поиск помогает
   найти официальный сайт, но не подтверждает личное расписание.
2. Студент вводит логин, пароль и код в нативные поля BotAI —
   сервер переносит их на страницу входа вуза в своём браузере. Пароль хранится
   зашифрованным для автоматического повторного входа; состояние браузера, включая
   ограниченные localStorage/sessionStorage, тоже защищено Vault. Капчу решает человек.
   По явной просьбе войти самостоятельно чат открывает защищённый экран. Успешная
   API-проба сама по себе не подтверждает вход на исходную страницу браузера.
3. Агент изучает доступные разделы, свежий DOM, наблюдаемые сетевые ответы и
   проверенные вкладки только на чтение, показывает этапы работы и
   ведёт подключение в обычном чате: принимает ссылки и уточнения текстом;
   секреты и конкретные подтверждения остаются защищёнными controls.
4. Итог — **рецепт**: декларативный JSON без личных значений (origin,
   наблюдаемые GET-эндпоинты или отрисованные HTML-страницы, разметка полей).
   Схема, lint и canary проверяют чтение на сессии студента; он подтверждает собранное.
5. Дальше студенты этого вуза синхронизируются по совместимому рецепту со своими
   сессиями — детерминированно, без участия модели.

У вуза может быть сколько угодно источников любого вида (решение владельца 31.10.2026): два календаря, несколько
таблиц, несколько кабинетов. Код этого пока не выполняет в полной мере, например, второй календарь предлагается как замена
первого; план переработки — [many-sources.md](docs/plan/many-sources.md).

Чего мы не делаем: не обходим капчу и защиту от ботов, не пишем код под
конкретный вуз, не выполняем write-действия без подтверждения человеком.
